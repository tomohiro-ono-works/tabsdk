# AI 用プロンプトの参照ルール設計案

- 作成日: 2026-09-30
- 状態: 承認済みの設計。実装コードは別ファイル
- 対象: 設定画面の「選んだ行から AI 用プロンプトを作る」機能
- 関連仕様: `docs/html_screen_spec.md` の「リネーム・フォルダ・階層を AI に考えてもらう」

## 目的と範囲

リネーム、フォルダ、階層の判断に使うルールを、人が編集しやすい Markdown ファイルとして管理する。顧客・商品などは、参照ルールを選ぶためのデータの分類とする。HTML の生成時に固定フォルダ内の `.md` ファイルを読み取り、生成された画面ではファイル名ごとのチェックボックスを表示する。選んだファイルの本文を、既存の AI 用プロンプトのテキストエリアにある「参照ルール」欄へ入れる。

初期の対象はデータソースタブのリネーム・フォルダ・階層用プロンプト。計算フィールド用への後続の拡張は末尾に記す。設定 YAML の出力・適用は対象外とする。既存の行選択、`||` 区切りの入力・出力、コピー操作は維持する。Tableau のデータソース名はプロンプトに追加せず、ルールファイルの自動選択にも使わない。

## 既存画面との接続

現在の `export_html()` は Python で単体の HTML を生成し、ブラウザーでは `file://` でもオフラインで開ける。画面仕様では、外部ファイルの参照とサーバー起動を行わない。ブラウザーから固定フォルダを列挙する方式は、この制約に合わない。

そこで、**HTML 生成時に Python が固定フォルダを列挙して Markdown の本文を読み、ファイル名と本文を HTML に埋め込む**。ブラウザーは埋め込まれた一覧からチェックボックスを作る。MD を追加・変更・削除した内容は、次に HTML を生成したときに反映される。生成済み HTML の表示中には自動更新しない。

配置先は `twbpatch/template/prompt_rules/`。この直下の `.md` だけを対象とし、サブフォルダは走査しない。表示順はファイル名の昇順とし、チェックボックスのラベルには拡張子を含むファイル名を表示する。このフォルダを配布物にも含める。

```text
twbpatch/template/
├── prompt_rules/
│   ├── 00-common-rules.md
│   ├── 10-customer-data.md
│   └── 20-product-data.md
└── calc_prompt_rules/
    └── 00-calculation-rules.md
```

初期状態は共通ルールをチェック済み、顧客データ・商品データを未選択とする。共通ルールも利用者が外せる。今後ファイルを追加した場合は、既定で未選択とする。

## Markdown の書き方

Markdown 表は使わず、見出し・箇条書き・インデントを使う。1 ファイルに一つの適用範囲を持たせる。ファイル本文は、整形や要約をせずプロンプトへそのまま入れる。

### 共通ルール: `00-common-rules.md`

- 日本語表記、表記ゆれ、同じ意味の項目・フォルダの重複禁止
- フォルダの番号・大きさ・ディメンションとメジャーの分け方、階層の付け方
- 既存のフィールド名との衝突時の扱い
- 判断できない項目の扱い
- 「データソース構造」の読み方

データソース構造は、フォルダの下に階層、階層の下にフィールドを書く。階層に属さないフィールドはフォルダの直下に書ける。インデントが深い項目は直前の浅い項目に属し、同じ深さの項目は同じ親に属する。フォルダと階層の名前には末尾の `/` を付け、フィールド名には付けない。フォルダと階層の区別は、深さと見出しから読む。

```text
データソース
　フォルダ/
　　階層/
　　　フィールド
　　階層に属さないフィールド
```

この構造は、Tableau のフォルダ・階層・フィールドの関係を人と AI に伝えるための記法であり、Markdown 自体を設定 YAML として解析・適用するものではない。階層に入れるフィールドの順番は、上位から下位へのドリルダウン順とする。既存画面の制約である「一つの階層に 2 フィールド以上」「同じ階層のフィールドは同じフォルダ」も共通ルールに記載する。

### データ別ルール: `10-customer-data.md`、`20-product-data.md`

各ファイルは顧客・商品などの分類を一つ扱い、次の見出しにそろえる。分類は実際の Tableau データソース名との一致を要求しない。

```md
# 顧客データ

## 適用対象
- 顧客、契約、問い合わせに関するフィールド。

## データソース構造
顧客データ
　01_顧客/
　　顧客階層/
　　　顧客区分
　　　顧客名
　　顧客コード

## 項目名の対応辞書
- 入力項目：顧客名、会社名、取引先名
  - 変換後：顧客名

- 入力項目：名称
  - 変換後：顧客名
  - 条件：顧客本人または顧客企業の名称を表す場合
```

対応辞書の必須項目は「入力項目」と「変換後」のみ。「条件」は選択した分類の中でも同じ語が異なる意味になる場合だけ付ける。「対応先」「リネーム後」「補足」は設けない。辞書の「変換後」はフィールドの表示名を指し、フォルダと階層は同ファイルのデータソース構造から判断する。辞書に無い入力名は、共通ルールと構造を参照して提案する。

商品データも同じ構成で、適用対象、商品データの構造、商品用の対応辞書を書く。上記の内容は書式例であり、具体的な顧客・商品用語や分類は実際のデータに合わせて作成する。

## 画面とプロンプトの動作

1. 「選んだ行から AI 用プロンプトを作る」を押すと、従来どおり選択行の情報から基礎プロンプトを作る。
2. ダイアログに Markdown ファイル名のチェックボックスを並べる。利用者が顧客・商品など、今回のフィールドに関係する分類を選ぶ。データソース名から分類を推測しない。チェック済みファイルの本文を、テキストエリア内の `# 参照ルール` 欄へファイル名付きで追加する。
3. チェックを変えたら、選択中のファイルだけから「参照ルール」欄を再構成する。外したファイルの本文は消し、同じファイルが重複して入らないようにする。選択がゼロなら欄自体を消す。
4. テキストエリア内の「参照ルール」欄以外は、チェックの変更では書き換えない。利用者は従来どおりテキストエリアを編集・コピーできる。
5. 「参照ルール」欄の内部を手で編集した内容は、次にチェックを変更した際に選択中の MD 本文から作り直される。欄の外に追記した文章は残す。
6. ダイアログを開き直して基礎プロンプトを作り直すと、その時点の行選択とチェック状態を反映する。計算フィールド用ボタンから開いた場合の後続仕様は末尾を参照する。

「参照ルール」欄には開始・終了を識別できる境界を設け、チェック変更時にその範囲だけを置き換える。利用者が境界を削除した場合は、テキストエリア全体を推測で書き換えず、プロンプトの再生成を案内する。

参照ルールは命名・分類の判断材料として使う。入力行数・順序・`||` 区切り・出力 4 列という既存の出力契約は基礎プロンプトに残す。命名・分類の共通方針は `00-common-rules.md` だけに置き、選択したデータ別ルールの具体的な用語と構造を適用する。複数の分類を選んだ場合は各フィールドに該当する適用対象と条件を使い、候補を判別できなければ元名を維持してフォルダ・階層は空欄にする。

## 読み込みと異常時の扱い

- 対象ファイルは固定フォルダ直下の `.md` のみ。UTF-8 で読み込む。
- フォルダが空ならチェックボックスは表示せず、既存のプロンプト生成は使える。
- MD の読み込みに失敗した場合は、欠けたルールで HTML を生成せず、対象ファイル名を含むエラーを返す。
- 埋め込む本文は HTML のタグやスクリプトとして解釈されない形式にし、`</script>` などが含まれても生成 HTML を壊さない。
- MD はプロンプトへの参照資料であり、`.twb` の変更や設定 YAML の生成には直接使わない。

## 設計時点の確認事項

- 共通ルールを初期チェック済みにする案は、以前の提案を引き継いだ。必要なら全件未選択に変更できる。
- データ別ファイルの具体的な用語と階層は、実データを見て記入する。ここでは書式だけを定める。

## 計算フィールド用への拡張（2026-09-30）

- 計算用の参照ルールは `twbpatch/template/calc_prompt_rules/` 直下の `.md` とし、リネーム用のフォルダとは分ける。
- `00-calculation-rules.md` に、既存の基礎プロンプトにあった IIF、集計、ゼロ除算、命名などの具体的な計算ルールを置く。初期状態ではチェック済みにし、従来の計算ルールを維持する。
- 計算用ボタンから開くと計算用ファイル名のチェックボックスだけを表示し、選択した本文を同じ境界付き `# 参照ルール` 欄へ入れる。リネーム用と計算用のチェック状態は別々に保持する。
- 計算用の基礎プロンプトには、使えるフィールド、作りたい指標、出力 5 列と `||` 区切りの契約を残す。チェックを全て外してもその契約は変えない。
- 具体的な計算式例は計算用 MD に集め、基礎プロンプトにはデータ型・役割の選択肢を含む出力形式だけを残す。
