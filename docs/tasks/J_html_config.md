## 目的

ダッシュボードを組む前に、データソースのフィールドを調べて Python コードへ手で書き写す作業が
発生している。フィールドが数十個あると現実的でない。
**HTML を出力し、画面で設定して設定ファイルを吐かせる**ことでこれを置き換える。

その後、画面仕様として次の 4 つが要望として出た。

| # | 画面 | 内容 |
|---|---|---|
| 1 | 全体 | （内容未定） |

これは当初の範囲 a を超え、2 と 3 が範囲 b、4 が範囲 c〜d に当たる。

## 進め方を「画面が先、受け手が後」に変えた（2026-09-06）

起票時は二段構え（データソース設定を先、ダッシュボード設定は土台 3 件の後）としていた。
実装中に **HTML を先に全部作り切る**方針へ変えた。

**理由**: 受け手が読む YAML の形は、画面が何を吐くかで決まる。画面が動いているうちに
受け手を書くと確実に書き直しになる。逆に画面を固めれば、受け手は決まった形を読むだけになる。

**ダッシュボード側の土台 3 件（K-1 / H-10 / H-1）待ちは解消していない。**
ただし画面は「出力する YAML の形は後から変わってよい」という前提で作ってあり、
Python 側で依存しているものが何も無いため、画面だけ先に進めても手戻りが閉じる。

**計算フィールドの役割問題も 2 周方式で解けた。**

```
1周目  データソースを設定 → YAML → .twb へ適用して保存
2周目  適用後の .twb から export_html() し直す → 計算フィールドが実在フィールドとして出る
```

式から役割やデータ型を推測する処理は要らない。

## 共通の制約

- **外部依存を増やさない。** 現在の依存は `lxml` と `PyYAML` のみ。
  HTML は文字列として生成し、CSS と JavaScript はインラインに埋め込む。
  テンプレートエンジンも CDN も使わない（オフラインで開けること）。
  **表計算ライブラリ（Handsontable 等）は使えない。セル状の表は自前で書く。**
- **サーバを立てない。** ブラウザからのダウンロードで設定ファイルを受け渡す。
- 出力した HTML は単体で完結し、他のファイルを参照しない。
