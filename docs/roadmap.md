## 3 つの方針

### 1. 壊れるものを先に消す

サンプル 20 本は、実行するとリポジトリ外の実ワークブックを `overwrite=True` で上書きする。
フックで止めてはいるが、**削除すれば根本的に消える**。着手前に片付ける。

### 2. 同じファイルを 2 つの作業で同時に触らない

調査で判明した衝突。

| 作業 | 触るファイル |
|---|---|
| A-6（改名） | `connected_worksheet.py` / `connected_dashboard.py` |
| A-2（モデル化） | `connected.py` / `connected_worksheet.py` / `connected_dashboard.py` |
| K（帳票） | `connected_dashboard.py` の `build_report()`（`:766`〜） |
| H-10（グラフ） | `draw.py` / `workbook.py` |
| **J（HTML 設定）** | **`serialization.py` + 新規ファイルのみ** |

**`build_report()` は改名対象の `update_style()` を 3 箇所で呼んでいる。**
K 群を A-6 より先にやると、同じコードを 2 度書き直すことになる。

### 3. 価値の出る作業を止めない

**J 群（HTML 設定）はどの作業とも衝突しない。** 土台の整備を待たずに並行して進められる。
基盤整備だけで数週間止まるのを避けるため、Phase 0 の直後から別トラックで走らせる。

```
H-1 (ダッシュボードアクション)
  ├→ I-1 (リセットボタン)      … アクション設定が必須
  └→ I-3 (ヘッダーメニュー)    … リンクにアクションが要る場合
```

**I-2（KPI ツリー）が最も大きい。** H-10 と K が固まってから着手する。
3 つに割れる: 階層定義の入力形式 / ノード 1 個分のシート群 / 左→右のツリー配置。
