## 目的

指標の親子関係を設定画面で組み、設定 YAML の `kpi_tree:` 節を経由して、
左から右へ展開したツリー型ダッシュボードを `.twb` に作る。

**KPI ツリーの役割は「KPI カードをツリー状に正しく配置する」ことだけ**（2026-09-13 決定）。
カードは既存の `draw_card()` でそのまま作り、KPI ツリー専用のグラフは作らない。

## 決めたこと（2026-09-13）

### ~~D1. 親ノードの位置を .twb にも反映するか~~ → 反映する

今の `draw_kpi_tree()` は、横並びコンテナの中のカードが**子の合計の高さまで伸びる**。
画面のような「決まった大きさのカード」にならず、上端モードも表現されない。

画面で選べるのに出力に効かないと、選んだ意味が伝わらない。**タイル配置のまま**、既存の
`add_spacer()` と `fixed_size` で組む（浮動配置は使わない。仕様 §6.13 の標準に従う）。

```
横コンテナ
├ 縦コンテナ（fixed_size = ノードの幅）
│   ├ カード（fixed_size = ノードの高さ）
│   └ 空白 add_spacer()        ← 上端のとき。中央なら「空白 / カード / 空白」
└ 縦コンテナ（子ノードを積む）
```

タイル配置ではコンテナの最後の子が残りいっぱいに伸びるため、カードの大きさを固定し、
余りを空白で埋めて位置を揃える。

### ~~D2. ノードとダッシュボードの大きさ~~ → 固定値と自動計算

- **ノードの大きさは全ノード共通で 横 200 × 縦 150 に固定する**（当初 400 × 300、2026-09-14 に半分へ）。引数にも画面にも出さない。
  ノードごとに変えられるようにすると、兄弟でカードの高さがばらつき、エッジや上端の揃いが崩れる
- **ダッシュボードの大きさはツリーの形から計算する。** 幅 = 階層の深さ × 200、
  高さ = 末端ノードの数 × 150（＋台紙の余白）。固定サイズの合計が入りきらない状態を作らないため
- エッジ列を入れると幅の式が変わる（E4）

### ~~D3. ノードのアクション~~ → 今回は持たない

KPI カードはメジャーだけでディメンションを持たないため、フィルターアクションの送り元にならない。
URL を開くアクションなら付けられるが、需要が出てから考える。画面・YAML・受け手のいずれにも持たせない。

### ~~D4. `KpiNode` の形~~ → シートと子だけを持つ

`KpiNode` に `draw_card()` の引数を写すと、実質 KPI ツリー専用のカードを作ることになる。
**ノードが持つのは、先に `draw_card()` で作ったシートと、子ノードだけにする。**
ダッシュボードタブの `build_report()` が「既にあるシートを並べるだけ」なのと同じ分担になる。

### ~~D5. シート名の重複~~ → 画面で両タブを横断して検証する

ダッシュボードタブと KPI ツリーは同じワークブックにシートを作る。同じ名前があると、
適用の途中で `create_worksheet()` が例外になって止まる。
**ダウンロード前に両タブをまたいで重複を検証し、エラー欄に出してダウンロードを止める。**
出し方はダッシュボードタブの既存の検証（`validateDashboard()`）に揃える。

### ~~D6. 配置 API の名前と置き場所~~ → `TwbWorkbook.build_kpi_tree()`

- `draw_` を外す。`draw_*()` はグラフ生成の仲間で、設定画面が `dir(TwbWorkbook)` から
  グラフ種類の一覧を作る
- `build_` は `build_report()`（既存シートからコンテナとゾーンを組む）に揃える
- `TwbDashboard` ではなく `TwbWorkbook` に置く。`TwbDashboard.update()` は大きさを変えられないため、
  大きさを計算してから `create_dashboard()` する

## エッジ（線）— 2026-09-13 に範囲へ入れた

ノードの配置を Tableau で確認したところ、線が無いと親子関係が読み取れないため範囲へ入れた。

### 方式: エッジ専用のデータソースを使った折れ線グラフ

| 検討した方式 | 見送った理由 |
|---|---|
| 色付き空白（`add_spacer(style=...)`）で線を組む | ノード 1 つにつき細い空白が数個ずつ増え、Tableau 上での手直しがつらい |
| 画像（`add_image()`） | 画像ファイルを指定する API が無い。.twb の外のファイルになり、パスとパッケージの問題が出る |
| 業務データで折れ線を描く | 線の点のデータが無い。データソースフィルターで行が消えると線も消える |

**エッジの座標だけを持つ表（`examples/edge.hyper`）を、ライブラリがデータソースとして足す**（2026-09-13 訂正。
当初「ユーザーが Tableau で足す」としたのは誤り）。一般的なデータソース作成（backlog H-2）は不採用のまま、
クラス方式に .hyper 専用の `TwbWorkbook.create_hyper_datasource()` を足し、API 方式がそれを使う。
.hyper の中身は読めないので、列（edge / point / x / y）は呼び出し側が宣言する。業務データのフィルターの影響も受けない。
親ノード 1 つにつきエッジ用ワークシートを 1 枚作り、ノード列と子の列のあいだの「エッジ列」に置く。

```
横コンテナ
├ ノード列（400）
├ エッジ用シート（幅 = エッジ列、高さ = 行いっぱい）   ← 子がいるときだけ
└ 子の列
```

**座標は 150px（カードの高さの半分）単位の整数で足りる。** 親の行の上端から数えたカードの中心は、
中央揃えで「2 ×（前の兄弟の末端数の合計）+ 自分の末端数」、上端揃えで「2 ×（前の兄弟の末端数の合計）+ 1」になる。

### ~~E1. 線の形~~ → 直角（2026-09-13）

ユーザーが Tableau で手作りしたシート「ツリーエッジ」（`outputs/kpi_tree_top.twb`）で決まった。
折れ線を**階段補間**にして、親から横 → 縦の幹 → 子へ横の直角を作る。承認済みの画面の試作と同じ形。

### ~~E2. 表の形~~ → 親を原点に置き、子の縦位置だけを変える（2026-09-13）

ユーザーが作った表（元はクリップボードからの貼り付け。抽出は `examples/edge.hyper`）:

| 列 | 中身 |
|---|---|
| `edge` | 線の ID。`E-k` |
| `point` | 点の名前。`O` / `P-k` / `P2-k` |
| `x` | 0 = 親カードの右端 / 1 = 幹 / 2 = 子カードの左端 |
| `y` | 親の中心からの縦の距離（150px 単位）。O は 0、`P-k` と `P2-k` は k |

線 1 本 = O(0, 0) → P-k(1, k) → P2-k(2, k) の 3 点。k は 0〜13。エッジ用シートでは、その親の子の
縦位置の分だけ `edge` をフィルターで残す（例: 末端 1 つずつの子 3 つを上端揃えで並べると `E-0` / `E-2` / `E-4`）。
**親を常に原点に置くので、表の大きさは子の縦位置の範囲に比例するだけで済む。**

### 手作りのシートの設定（XML で実測、2026-09-13）

| 設定 | 値 | ライブラリ |
|---|---|---|
| 行 / 列 | `SUM(y)` / `SUM(x)` | ある |
| マーク | 線（`Line`）。色 `#666666`、サイズ小 | ある（`pane.update(mark_type=, mark_color=)`、サイズ） |
| 詳細（LOD） | `edge` と `point` | ある |
| フィルター | `edge` を値で絞る | ある（`TwbWorksheetFilter.update(values=)`） |
| 軸の非表示 | x・y とも | ある（`set_axis_visibility()`） |
| 線の補間 | `line-interpolation=step` | **無い** |
| y 軸の反転 | 軸の `encoding reverse="true"` | **無い** |
| グリッド線・ゼロ線・ドロップライン・参照線 | すべて `line-visibility=off` | **無い** |
| 軸の範囲の固定 | 手作りのシートには無い（自動） | **無い**（前年差帳票の内部だけ） |

**軸の範囲の固定は、手作りのシートに無くても必要になる。** 自動の範囲は表示中の点に余白を足して決まるため、
線の端がカードの中心と縁にぴったり合わない。エッジ用シートの高さ（親の行の高さ）と、
y = 0 が親の中心に来ることから範囲は計算で決まる。上端揃えなら y は −1〜2 × 末端数 − 1、
中央揃えなら −末端数〜末端数。x は 0〜2。

### 決めること

#### ~~E3a. 中央揃えのエッジ~~ → 今回は扱わない（2026-09-13）

中央揃えでは親が子の範囲の真ん中に来るため、上側の子は親より上（k が負）になり、今の表では描けない。
**エッジは上端揃えだけで描く。** ノードの中央揃え（`align="center"`）はそのまま残し、
エッジ用データソースを渡したうえで中央揃えを指定したときは例外にする。

#### E3b. 表の範囲と置き場所

上端揃えでの子の縦位置は「2 ×（前の兄弟の末端数の合計）」で、常に 0 以上の偶数になる。
今の表（k = 0〜13）なら、**1 つの親の下の末端数は 7 まで**描ける。

**推奨: 表はユーザーが作ったものをそのまま使う。** 元データのテキストはリポジトリの外
（`マイ Tableau リポジトリ/データ ソース/Clipboard_20260913T210521.txt`）にあるので、`examples/edge.txt` へ写し、
ユーザーはそのファイルに接続して抽出を `examples/edge.hyper` に作る。
ライブラリは抽出の中身を読めないので、末端数が上限を超えるツリーは `build_kpi_tree()` が例外にし、
上限は仕様と README に書く。表を広げるときは上限の定数も同時に変える。

#### E4. エッジ列の幅

固定値にする（例: 60px）。ダッシュボードの幅は「深さ × 400 +（深さ − 1）× 60」になる。

#### E5. エッジ用データソースの渡し方

`build_kpi_tree(..., edges=None)` に `TwbDatasource` を渡す。`None` ならエッジを描かない
（エッジ用データソースが無いワークブックでも使える）。YAML は `kpi_tree.edge_datasource`。

#### E6. エッジ用シートの扱い

`build_kpi_tree()` の中で作る。配置と切り離すと意味を持たないため。名前は `エッジ|<親のシート名>` で、
シートのタブには出さない。仕様 §6.14 の「シートを作らない」は「KPI カードは作らない」へ直す。

#### E7. 線の色と太さ

固定値。Tableau での見た目確認で決める。

- 画面はデータソースの既存の計算フィールドとリネームを表に並べて毎回 YAML に出す。**同じデータソースの設定を
  2 回適用しても止まらず、計算フィールドも増えない**（上書き）。`docs/developer/html_screen_spec.md` と `docs/user/library/roundtrip.md` の
  「フォルダを 2 回渡すと `NotFoundError`」は今の実装と合わない
- ダッシュボード・KPI ツリーの節は上書きしない。同じ YAML を 2 回適用すると、2 回目は最初のシートで
  `worksheet already exists` になって止まる。名前が別なら、ダッシュボード用と KPI ツリー用を続けて適用して両方作れる

#### 決めたこと（2026-09-14）

- **YAML のダウンロードをタブごとにする。** ナビ右端の 1 つにまとめた決定（以前は項目ごとにあった）を改める

  | タブ | ダウンロードの中身 |
  |---|---|
  | データソース | `datasources` |
  | ダッシュボード | `design` + `datasources` + `dashboard` |
  | KPI ツリー | `design` + `datasources` + `kpi_tree` |

  デザインルールはカードの色の参照（`@main_color`）と余白に要るので、ダッシュボードと KPI ツリーに入れる。
  空のダッシュボードが増える問題もこれで起きない
- **名前の重複は画面で番号を付ける。受け手（`apply_config()`）では付けない。** 受け手で付けると、同じ YAML を
  誤って 2 回適用しても止まらずに「(2)」が黙って増え、アクションの対象シート（名前で指定）もずれるため。
  - シート名の自動生成（✎）は、重複したら「 (2)」「 (3)」…を付ける（今の「_2」を改める）
  - 重複を見る相手は、ダッシュボードタブ・KPI ツリータブの名前と、.twb に既にあるシート・ダッシュボード（`DATA`）
  - 手で入力した名前が重複したら、ダウンロード前の検証でエラーにする

#### 方針: タブの中身は別ファイルに置き、`html_export.py` には差し込み口だけ足す

KPI ツリーの API を `kpi_tree.py` に分けたのと同じ理由で、タブの HTML・CSS・JS は
**`twbpatch/html_kpi_tree.py`（新設）** に文字列として置く。`html_export.py` への変更は次の差し込みだけにし、
別セッションの変更とぶつかる範囲を小さくする。

| `html_export.py` の差し込み口 | 中身 |
|---|---|
| `<nav>` | 「KPI ツリー」ボタンを足す。右端のダウンロードボタンを外す |
| 各タブ | データソース・ダッシュボードのタブにダウンロードボタンを置く |
| `<main>` の末尾 | KPI ツリーのセクション（ダウンロードボタンを含む） |
| `_TEMPLATE` の style / script | KPI ツリーの CSS・JS を後ろにつなぐ |
| `buildYaml()` | `designYaml()` / データソース部分 / `dashboardYaml()` を、タブごとの組み合わせで出せるように分ける |
| `generateSheetName()` | 番号を「 (2)」にし、重複を見る相手に KPI ツリーと既存のシート・ダッシュボードを入れる。KPI ツリーからも呼ぶ |
| `dashboardYaml()` の `params` の書き出し | 関数に切り出して KPI ツリーと共用する（`draw_card` の色の複製を 2 か所に持たない） |
| `validateDashboard()` | 手で入力した名前の重複（両タブ・既存）を足す |

## YAML の形

```yaml
kpi_tree:
  name: "KPI ツリー"
  datasource: "EC Orders"
  align: "top"                    # center / top。top ならエッジを描く（.hyper は指定しない）
  root:
    sheet: "売上"
    params:
      main_metric: "売上(当年)"
      sub_metric: "数量(当年)"
      main_color: "@main_color"
      visible: true
    children:
      - sheet: "客数"
        params:
          main_metric: "客数"
        children: []
```

ノードの `sheet` / `params` は**ダッシュボードタブの `areas[].sheet` / `params` と同じ名前・同じ形**にする。
受け手はノードごとに `chart: "draw_card"` と `kpi_tree.datasource` を補って、
既存の `_draw_area()` にそのまま渡す。`chart` はノードに書かない（KPI カード固定のため）。
大きさ（ノード・ダッシュボードとも）は YAML に持たない。
