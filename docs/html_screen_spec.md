# 設定画面 HTML の設計書

- 作成日: 2026-09-06
- 対象: `twbpatch/html_export.py` と `TwbWorkbook.export_html()`
- 位置づけ: **実装済みの画面の仕様書。** 作業計画は `docs/tasks/J_html_config.md`

## 目的

ダッシュボードを組む前に、データソースのフィールドを調べて Python コードへ手で書き写す作業を
なくす。ワークブックの内容を画面に出し、**画面で設定して設定ファイルを吐かせる。**

## 全体像

```
1周目  wb.export_html("config.html")
         → データソースタブで表示名・フォルダ・計算フィールドを設定
         → 設定 YAML をダウンロード
         → Python で .twb へ適用して保存        ← 受け手は未実装
2周目  適用後の .twb から export_html() し直す
         → 計算フィールドが実在フィールドとして候補に出る
         → ダッシュボードタブで画面を組む
         → 設定 YAML をダウンロード             ← 受け手は未実装
```

**2 周に分ける理由**: 計算フィールドは 1 周目で `.twb` に焼くまで存在しない。
焼いてしまえば役割もデータ型も確定するので、**式から役割を推測する処理が要らない。**

## API

```python
TwbWorkbook.export_html(
    path,                      # 出力先
    *,
    title="twbpatch 設定",     # 画面と <title> に出す名前
    overwrite=False,           # 既存ファイルがあれば FileExistsError
) -> Path
```

仕様 §2.0 の **API 方式**。`serialize_workbook()` の結果を HTML へ整形するだけで、
クラス方式の上にしか建てていない。§6.14 の一覧に載る。

## 実装の制約

- **外部依存を増やさない。** 依存は `lxml` と `PyYAML` のみ。CSS と JavaScript は
  インラインで埋め込み、CDN もテンプレートエンジンも使わない。**オフラインで開ける。**
- **サーバを立てない。** 設定ファイルはブラウザのダウンロードで受け渡す。
- 出力した HTML は単体で完結し、他のファイルを参照しない。
- **ブラウザ側で `.twb` / `.twbx` を読ませない。** 技術的には可能（`DOMParser` と
  `DecompressionStream("deflate-raw")`）だが、フィールドの取り出しは接続の
  `metadata-record` との突き合わせを含むため、JavaScript へ写すと Python と
  二重管理になってずれる。**解析は Python 側に置く。**

## 画面の構成

固定ヘッダー（`position: sticky`）に 3 つのタブと「設定 YAML をダウンロード」、
その右にワークブック名と件数が並ぶ。

| タブ | 中身 | 受け手 |
|---|---|---|
| 全体（デザインルール） | フォント・色・余白・フィルターの適用ボタン | フォントのみ実装済み |
| データソース | リネーム・フォルダ設定 / 計算フィールド | フォルダと表示名は実装済み |
| ダッシュボード | 新規ダッシュボードの構成 | 未実装 |

## 全体（デザインルール）タブ

ワークブック全体に効く書式。**データソース側でもダッシュボード側でもない第 3 の対象。**

| 項目 | 入力 | Python 側の受け手 |
|---|---|---|
| フォント | 選択式（19 件） | `set_default_font()` |
| メインカラー | 色見本 + 16 進表記 | **なし** |
| サブカラー①② | 同上 | **なし** |
| 通常時の文字色 | 同上 | **なし**（`set_default_font()` は `font-family` しか書かない） |
| ヒートマップ：最小値/中間/最大値の色 | 同上（既定 `#2166ac` / `#f7f7f7` / `#b2182b`） | **なし**。`draw_crosstab` の `min_color`/`mid_color`/`max_color` から `@min_color` 等で参照する専用（2026-09-12 追加） |
| フィルターに「適用」ボタン | チェック | **なし**。XML 上の表現も未調査 |
| 余白 | 多め / 少なめ | `build_report()` の `content_style` に相当 |

フォント候補は `FONT_CHOICES`。Tableau Desktop の既定（Tableau Book / Medium / Regular）と
Windows・macOS の日本語標準フォントを並べる。

色見本（`input[type=color]`）と 16 進表記は双方向に同期する。

## データソースタブ

データソースを選ぶと、その内容が 2 つの表に出る。**片方を開くともう片方が閉じる**
排他アコーディオン。データソースを切り替えても編集内容は保持する（`EDITS`）。

### セル状の表の共通仕様

| 操作 | 動き |
|---|---|
| 範囲選択 | ドラッグ / Shift+クリック / Shift+矢印 |
| コピー | Ctrl+C で選択範囲を TSV に。Excel へそのまま貼れる |
| 貼り付け | Ctrl+V で選択位置を左上に複数セル展開 |
| 消去 | Delete / Backspace（読み取り専用セルは変えない） |
| セルを選ぶ | クリック（1回目）。枠線が付くだけでキャレットは入らない |
| テキストを編集する | 選んだセルをもう一度クリック / F2 / 文字キー（置き換えて編集） |
| 編集をやめる | Ctrl+Enter または Escape（同じセルの選択に戻る） |
| セルの移動 | 矢印 / Enter / Tab（**選択中のみ**。編集中の矢印はセル内のキャレット移動） |
| セル内改行 | 編集中の Enter（Alt+Enter も同じ） |
| 元に戻す・やり直し | Ctrl+Z / Ctrl+Y（Ctrl+Shift+Z） |

**1クリック目は選択、2クリック目で編集**（2026-09-13 変更、Excel に合わせた）。
以前はセルが常に `contenteditable` で、1クリックで即キャレットが入っていた。
セルは既定では編集不可にし、**「編集できるセル」は `data-edit` 属性**で表す
（`editableCell()` / `readonlyCell()`）。`beginEdit()` がそのときだけ
`contenteditable` を付け、`endEdit()` が外す。したがって JS 側では
`isContentEditable` は「いま編集中か」、`isEditable()` は「編集できるセルか」を
意味する。選択中も矢印移動とコピーを効かせるため、セルには `tabindex="-1"` を
付けてフォーカスできるようにしてある。選んだセルは `td.active` の枠線、編集中の
セルは `td[contenteditable]` の背景色で見分ける。

**編集中はセルの外へ出さない**（2026-09-13 修正）。矢印キーはすべてセル内の
キャレット移動にする（上下は複数行の式の1つ上/下の行へ）。以前は編集中でも
上下キーが隣の行のセルへ飛んでしまい、複数行の式を直せなかった。編集を終えるのは
Ctrl+Enter（同じセルの選択へ戻る。そこから矢印でセルを移動する）と Escape。
Tab だけは Excel と同じく確定して隣のセルへ動く。

**編集中の Enter はセル内改行、確定は Ctrl+Enter**（2026-09-13 変更）。当初は
Excel に合わせて Alt+Enter だけを改行にしていたが、この表で複数行になるのは
主に式なので、書きやすさを採って入れ替えた。Alt+Enter は Excel の指の記憶に
合わせた別名として残してある。**選んでいるだけのとき（編集中でない）の Enter は
従来どおり1つ下のセルへ移動**するので、選択中の操作感は変わらない。

これに伴う周辺の調整:

- **コピーは1セルでも効く**。以前は範囲選択のときだけ自前でコピーし、1セルは
  キャレットが入っていたのでブラウザ既定に任せていた。選択モードではキャレットが
  無いので、選択があれば1セルでも自前でコピーする。編集中はセル内の文字選択を
  そのままコピーさせる
- **編集中の貼り付けはキャレット位置へ素のテキストで差し込む**。ブラウザ既定に
  任せると `<div>` や `<br>` が入り、`textContent` で読む側が壊れるため
- **候補ポップアップを閉じる処理は capture フェーズ**。選択が mousedown の中で
  `cell.focus()` を呼ぶようになり、その focus で開いたポップアップを、同じ
  クリックの続きで流れてくる「外側クリックで閉じる」処理が即座に閉じてしまって
  いた（1クリックでは候補が出ない）

**セル内改行は Alt+Enter**（2026-09-13 追加。主に式の複数行入力向け）。素の
`"\n"` テキストノードを挿入する（`<br>` にしない）。`textContent` は `<br>` を
無視して前後を連結してしまい、`captureInto()` など読み取り側で改行が消える
（式の複数行が1行に潰れる）ため。`white-space: pre-wrap` を
`td[contenteditable]` に指定し、素の改行を画面上でも折り返して見せる。
**コピー時、セル内の改行は行区切りの `\n` と区別しない**（既知の制限）。範囲コピー
に改行入りのセルが混ざると、貼り付け時に行がずれる可能性がある。

**`contenteditable` の既定の undo は使わない。** 貼り付けや行の増減を追えず表が壊れるため、
既定動作を止めて `tbody` のスナップショットを 100 手まで保持する自前の履歴に置き換えた。
連続入力は 500ms の無操作かフォーカスを外した時点で 1 手にまとめる。

**表計算ライブラリは使えない**（外部依存を増やさない制約）ので、上記はすべて自前実装。

**列幅はドラッグで変更できる**（2026-09-13 追加）。`table-layout: fixed` にし、
`<colgroup>` の `<col>` 幅を書き換える（`enableColumnResize()`）。最後の列は
残り幅を埋めるので境界の対象にしない。`<thead>` はデータの再描画
（`renderTables()`）では作り直さないため、ページ読み込み時に1回つければ持続する。

**判定は th 内の小さなつまみ要素ではなく、表全体への mousedown/mousemove で
「クリック位置が列境界の x 座標に近いか」を見る方式**（2026-09-13、2段階で
修正）。最初は `<th>` の右端に `.col-resize-handle` という子要素を置き、そこへの
ドラッグだけを拾っていたが、当たり判定が `<th>` の高さ（ヘッダー行1行ぶん）に
限られ、見た目の縦線（表の全行にまたがる）のごく一部でしかつかめずシビアだと
いう指摘を受けた。最終形では `boundaryAt(clientX)` が各列境界の x 座標との距離
（`COLUMN_RESIZE_HIT_ZONE`、左右10px。2026-09-13 に6pxから拡大）だけを見るため、
ヘッダーでも本文のどの行
でも、縦線の全長どこを押しても掴める。`enableGrid()` のセル選択
（`event.target.closest("td")` で始まる、bubble フェーズ）より確実に先に判定
できるよう、`enableColumnResize()` の mousedown は capture フェーズで登録し、
境界にヒットしたら `stopImmediatePropagation()` でセル選択を起こさせない。

境界 i のドラッグは **col[i] と col[i+1] の幅の合計を変えず、2列の間だけで
やり取りする**（2026-09-13 修正）。当初は動かした列だけを % から px 固定に
変えていたが、他の列は % のまま残るため、`table-layout: fixed` が「列幅の合計を
表の幅に一致させる」ために動かしていない列（特に左隣）まで勝手に再配分して
しまう実害があった。`enableColumnResize()` は全列の幅を実測 px へ固定してから、
以降は隣接する2列間だけで幅を移し替える。最小幅（`COLUMN_RESIZE_MIN_WIDTH`）は
動かす側・動かされる側の両方に効くので、広げすぎて隣の列を潰すこともできない。
`<col>` は非表示要素で `getBoundingClientRect()` が使えないため、対応する `<th>`
の実測幅を使う。

**「全列を実測 px へ固定する」処理はドラッグを始めるたびに呼び直す**
（`freezeAllColumnWidths()`、2026-09-13 修正）。当初はページ読み込み時に1回
だけ呼んでいたが、計算フィールド表（`#calc-table`）はアコーディオンが既定で
折りたたまれている（`.acc-body { display: none; }`）ため、その間は
`getBoundingClientRect()` が 0 を返し、全列が幅0pxのまま固定されてしまった。
後で列を1つ動かすと「指定した合計（実質0）が表の幅に足りない分」の帳尻合わせで
他の列が一気に広がって壊れる実害があった。表が畳まれた状態で固定を1回きりにせず、
実際にドラッグを始めた（＝表が確実に見えている）タイミングで毎回撮り直すことで
解決した。

### リネーム・フォルダ設定

| 列 | 編集 |
|---|---|
| 元カラム | 読み取り専用（XML の `@name` から角括弧を外したもの） |
| リネーム後名称 | 編集可 |
| フォルダ | 編集可。既定値は「フォルダ未指定」。フォーカスすると入力済みのフォルダ名一覧＋「フォルダ未指定」をクリックで選べる候補が出る（自由入力も可） |
| データ型 / 役割 | 読み取り専用 |

**非表示列は表示しない**（2026-09-13 削除）。読み取り専用の情報列で、リネーム・
フォルダ設定の判断に使わないため外した。非表示フィールド自体は引き続き一覧に
含まれる（除外はしない）。

**フォルダが「フォルダ未指定」の行は `renames`、それ以外は `folders` へ出力する**
（2026-09-08 決定）。`apply_field_config()` の設定形式は「フォルダ名 → {元カラム名: 表示名}」
の3階層固定でフォルダなしを表現できないため、フォルダに入れずに改名だけしたい場合の
入口を別セクションにした。表示名が空の行はどちらにも出力しない。

画面側で検証する（`apply_field_config()` が例外にする条件を出力前に防ぐ）。**フォルダが
「フォルダ未指定」の行はこの検証の対象外**（フォルダに割り当てないため）。

- フォルダを指定した行で表示名が空 → セルを赤くしてエラー欄に出す
- 同じフィールドを 2 つのフォルダに割り当て → 同上

### 計算フィールド

列は 名前 / 式 / フォルダ / データ型 / 役割（2026-09-12 順序変更）。既存の計算フィールドを
初期表示し、空行を 3 行足す。「行を追加」と「選択行を削除」。貼り付けで行が足りなければ自動で増える。

**役割とデータ型は自動判定しない。** `create_calculated_field()` は `datatype="real"` /
`role="measure"` の固定既定を持つだけで、式を読んでいない。式から戻り値の型を推論するには
Tableau の関数を一通り実装することになるため、**画面で入力してもらう。**

フォルダ・データ型・役割はいずれもフォーカス時に候補ポップアップが出る（自由入力・
コピー貼り付けは維持）。

- **フォルダ**: リネーム・フォルダ設定タブと同じ候補（入力済みフォルダ名＋「フォルダ未指定」）。
  検証はしない。「フォルダ未指定」の行は YAML 出力時に `folder` キーを出さない
- **データ型**: `string` / `integer` / `real` / `boolean` / `date` / `datetime`
- **役割**: `measure` / `dimension`

データ型・役割は自由入力を許すが、候補にない文字列を入れるとセルが赤くなり、
「設定 YAML をダウンロード」を押すとエラー欄に出て止まる。

## ダッシュボードタブ

**新規に組む専用。** 既存ダッシュボードの読み込み・編集はしない。

```
ダッシュボード   名前 / 幅 / 高さ
ヘッダー         タイトル / 高さ / 背景色 / 文字色
ボディ（縦段組）
  段             名前 / 高さ / 折り畳み / 並べ替え / 削除
    エリア       グラフ または フィルター
```

### 段とエリア

- 段もエリアも掴み手（⠿）でドラッグして並べ替える。**エリアは別の段へも移せる。**
  落とす位置は青い線で示す
- 掴み手を押したときだけ `draggable` を立てる。カード全体を常時 `draggable` にすると
  入力欄の文字選択ができなくなるため
- 段は折り畳める。畳むと見出しに「エリア N 件」だけが残る
- エリアの表示幅は **360px 固定**で、段の中を横スクロールする
- px の入力（ダッシュボードの幅・高さ、段の高さ、エリアの幅）は 10 刻み。
  既定は段の高さ 300、エリアの幅 600
- エリアは「複製」ボタン（⧉）で同じ段の直後にコピーできる（2026-09-08 追加）。
  `params` / `action` を含めて複製し、シート名はそのままコピーする（重複チェックは
  シート名生成ボタン側で行うため、複製時点では変えない）

### エリアの中身

| 種別 | 入力 |
|---|---|
| グラフ | シート名 / グラフ種類 / データソース / グラフパラメータ |
| フィルター | データソース / フィールド |

**シート名は右隣のボタン（✎）でグラフ種類と選んだ項目から自動生成できる**（2026-09-08
追加、手入力も可）。`{短縮ラベル}|{フィールド名}`（複数は `×` で連結）の形。

| グラフ | 短縮ラベル | 使うフィールド |
|---|---|---|
| スコアカード (`draw_card`) | スコア | `main_metric` |
| 棒グラフ (`draw_bar`) | 棒 | `item`, `metric` |
| 前年比の時系列 (`draw_yoy`) | 時系列 | `metric`（メイン指標①のみ） |
| 散布図（四象限） (`draw_quadrant`) | 象限 | `x_metric`, `y_metric` |
| クロス集計（ヒートマップ） (`draw_crosstab`) | クロス | `x_item`, `y_item` |
| 帳票 (`draw_sheet`) | 帳票 | `items`（先頭2件） |
| 前年差帳票 (`draw_colored_yoy_sheet`) | 前年差 | `metrics`（先頭1件のみ） |

未選択のフィールドは無視して、選ばれた分だけで組む。同名シートが既にあれば
末尾に連番（`_2`, `_3`, ...）を付ける。

区分値は `worksheet` / `filter`。**`build_report()` の項目の区分値と同じ言葉**を使う
（画面の表示は「グラフ」「フィルター」のまま）。1 つの段に混ぜてよい。

### アクション設定

どちらのエリアもアクションを 1 つ持てる。種類は**フィルターと URL を開くの 2 つ**。
ハイライトは受け手（`dashboard.create_action()`）が無いので画面に出さない。

| 種類 | 入力 |
|---|---|
| フィルター | 対象シート名 / 絞り込むフィールド |
| URL を開く | URL |

**フィールドは必須。** Tableau の「すべてのフィールド」は使わない前提のため
（2026-09-07 決定）、指定なしのフィルターアクションは作れない。
候補はエリアのデータソースのディメンションに絞る。

### グラフパラメータの入力欄は自動生成する

**手で書き写した引数一覧を持たない。** `_draw_specs()` が `TwbWorkbook.draw_*()` の
シグネチャを `inspect` で読み、入力欄の種類を型注釈から決める。

| 型注釈 | 入力欄 |
|---|---|
| `list[FieldInput]` | フィールドの複数選択（チェックボックス付きプルダウン、下記） |
| `FieldInput` | フィールドの選択 |
| 引数名が `_PARAM_CHOICES` にある | プルダウン選択（下記） |
| 名前が `colors`（複数形） | 色見本を4つ並べる（下記） |
| 名前に `color` を含む | 色見本 + デザインルールの参照 |
| `bool` | チェックボックス |
| `float` / `int` | 数値 |
| その他 | テキスト |

`draw.py` に引数が増えれば画面も自動で増える。

**値が固定の選択肢しかない引数はプルダウンにする**（2026-09-12 追加）。`_PARAM_CHOICES`
に登録した引数だけが対象で、値は API 側のバリデーションと一致させる。

| 引数 | 選択肢 | 対応する関数 |
|---|---|---|
| `item_shelf` | 横棒（行）/ 縦棒（列） | `draw_bar` / `draw_yoy` / `draw_sheet` |
| `mark_type` | 棒 / テキスト | `draw_colored_yoy_sheet` |

登録が無い自由入力の引数（`date_level` など）は、値の候補が今のところ1つしか無いか
未整理のもの。候補が増え次第 `_PARAM_CHOICES` に追加する。

**色を指定できないグラフには引数を足す**（2026-09-12、`draw_bar` に `bar_color` を追加）。
色付けの必要なグラフに色引数が無ければ、API 側の見落としとして `draw.py` に追加する。

**`draw_quadrant.colors`（4色必要）は単一色ピッカーにしない**（2026-09-12 修正）。
名前に `color` を含むという判定だけだと `colors` も単一色ピッカーになり、4色を
指定する手段が画面から失われる実害バグだった。`colorsControl()` が色見本を4つ
並べ、`area.params.colors` に4要素の配列で保持する。既定値は API 側と同じ
`["#4400FF", "#FF007F", "#00C888", "#CCD500"]`。

**4色ピッカーには象限ラベルを付ける**（2026-09-12 追加）。`draw.py` の
`quadrant_formula` は x/y の中央値との大小比較で `colors[0]`〜`[3]` を
右上・左上・左下・右下の順に固定して割り当てる（`QUADRANT_COLOR_LABELS`）。
ラベルが無いと4つ並んだ色見本のどれがどの象限かわからず、意図と違う配色に
なりやすい。順序を変えるときは `draw.py` 側の割り当てとこのラベル配列を
同時に直す。

**`draw_crosstab` の min/mid/max_color は3つ揃えるかゼロかを検証する**
（2026-09-12 追加、`validateDashboard()`）。`draw.py` 側に同じ制約（3つ未満だと
`ValueError`）があるのに画面は未検証で、2色だけ入れた状態のまま保存できてしまい、
`apply_config()` のエラーで初めて気づく状態だった。

**`draw_crosstab` の min/mid/max_color は既定でデザインルールの3色を参照する**
（2026-09-12 追加）。3つ揃えるかゼロかしか許されない制約があるのに、グラフを
置くたびに3色を手入力させるのは非現実的だった。グラフ種類で「ヒートマップ付き
クロス集計」を選んだ瞬間、`defaultParamsFor()` が `min_color`/`mid_color`/
`max_color` を `@min_color`/`@mid_color`/`@max_color`（デザインルールタブの
ヒートマップ既定3色、既定 `#2166ac` / `#f7f7f7` / `#b2182b`）で自動的に埋める。
グラフ側で「個別に指定」に切り替えれば、そのグラフだけ別の3色にできる
（`_DESIGN_TOKENS` に `min_color`/`mid_color`/`max_color` を追加、`config_apply.py`）。

**画面に出さないもの**

- `datasource` / `name` — エリアの他の欄で指定する
- **`aggregation` / `*_aggregation`** — フィールドの役割とデータ型が分かっていれば
  `draw.py` の `_auto_metric_aggregation()` が決められる。人が選ぶ必要がない
- **`draw_card` の `value_color` / `title_background_color`**（2026-09-12,
  2026-09-13）— 指標名・数値・タイトル背景の色は揃える運用にし、画面では
  `main_color` の1つだけ入力させる。YAML 出力時に `main_color` の値を
  `value_color` と `title_background_color` にもそのまま複製する
  （`dashboardYaml()`）。**`draw_card()` 自体は3つの引数を持ったまま**で、
  Python 側の変更はしていない
- **`draw_card` の `vertical_alignment`**（2026-09-13 追加）— 「縦は常に中央で
  よい、選ぶ必要がない」との指摘を受けて画面から外した。API 既定の `"center"`
  のまま渡すので YAML には出さない

**必須と任意を分ける。** 必須だけ前面に出し、任意は「詳細設定」に畳む。
棒グラフなら前面は項目とメジャーの 2 つだけになる。

### フィールドの候補は役割で絞る

`_PARAM_ROLES` が、引数ごとにディメンションとメジャーのどちらを求めるかを持つ。

| 引数 | 候補 |
|---|---|
| 項目 / 横の項目 / 縦の項目 / 順位の区切り | ディメンションのみ |
| メジャー / 主メジャー / 横軸のメジャー / 色のメジャー など | メジャーのみ |

非表示のフィールドは候補から外す。フィルターのフィールド欄は種類を問わないので絞らない。

**フィールドの候補はフォルダごとに `<optgroup>` でまとめる**（2026-09-12 追加）。
プルダウンは1つのまま、フォルダを見出しにしてフィールドを分類する。フォルダ未指定の
フィールドは最後の optgroup にまとめる。フォルダの並びは五十音順、フォルダ未指定が最後。

**複数選択（`list[FieldInput]`）は `<select multiple>` を使わず、左＝候補・
右＝選択済みのモーダルにする**（2026-09-13、2段階で修正）。まず Ctrl+クリック
でないと複数選べず既定で4行程度しか見えない使いにくさを、チェックボックス付き
プルダウンに置き換えて解消した。しかしチェックボックスの並びは「五十音順の
候補一覧」であって「選んだ順」ではないため、`items`（土台シートの並び順）や
`metrics`（帳票の行順）のように**選んだ順序がそのままシート上の配置順になる**
引数では、並び順を指定する手段が無いという指摘を受けた。

最終形は `openFieldOrderModal()`。左リストに未選択の候補（`groupedFields()` で
フォルダごとにグループ化、単一選択の optgroup と共有）、右リストに選択済みを
**選んだ順に**並べる。左→右のドラッグで追加（ダブルクリックでも追加できる）、
右リスト内のドラッグで並べ替え、右の「×」または右→左のドラッグで外す。
右リスト内の並べ替えは、既存の段・エリアの並べ替え（`moveAreaTo()` などと同じ
「ドロップ位置が要素の上半分か下半分かで前後を決める」方式）に揃えた
（`modalDropTarget()`）。`fieldsCheckControl()` のボタン（選択件数を表示）を
押すとこのモーダルを開く。

### 表示はすべて日本語

`_CHART_LABELS` と `_PARAM_LABELS` が `draw_bar` → 棒グラフ、`item` → 項目 のように訳す。
英語名は `title` 属性に残す。**訳し漏れがあると英語名がそのまま画面に出る**ため、
漏れが無いことをテストで固定している。

### 色はデザインルールを参照できる

色の引数は「個別に指定」と「デザインルールのメインカラー / サブカラー①② / 文字色 /
ヒートマップ最小値・中間・最大値の色」を選べる（`DESIGN_TOKENS`）。
参照を選ぶと `@main_color` のような文字列として保存し、色見本にはデザインルールの値を映す。
デザインルール側を変えると即座に反映する。

```yaml

# 受け手: wb.apply_config() がこのファイルを読んで .twb へ反映する。
# design の色・余白・適用ボタンは dashboard を組むときに使う。

  sub_color_1: "#4a7dff"
  sub_color_2: "#c0c0c0"
  text_color: "#333333"
  filter_apply_button: false
  spacing: "wide"          # wide / narrow

datasources:
  "データソース名":
    folders:
      "フォルダ名":
        "元カラム": "表示名"
    renames:              # フォルダ未指定（フォルダへ入れず改名だけ）
      "元カラム2": "表示名2"
    calculations:
      - name: "利益率"
        formula: "SUM([利益]) / SUM([売上])"
        datatype: "real"
        role: "measure"
        folder: "指標"

dashboard:
  name: "ダッシュボード"
  width: "1600"
  height: "900"
  header:
    title: ""
    height: "43"
    background_color: "#c0c0c0"
    font_color: "#333333"

    - name: "上段"
```

## 画面の出力と受け手の対応

**画面が出す値がすべて受け手の引数に届くかを確認した（2026-09-07）。**

| 画面 | 受け手 |
|---|---|
| `dashboard.name` / `width` / `height` | `create_dashboard()` |
| `dashboard.header.title` | `build_report(header_title=)` |
| `header.height` / `background_color` / `font_color` | `build_report(header_*=)` |
| `rows[].name` | `struct` のキー |
| `rows[].height` | `struct` の `height` |
| `areas[].kind` | 項目の `kind`。**同じ言葉を使う**（`worksheet` / `filter`） |
| `areas[].width` | 項目の `sheets` + `fixed_size`（1 枚の列にする） |
| `areas[].sheet` / `chart` / `params` | `draw_*()` の `name` と引数 |
| `areas[].field`（フィルター） | 項目の `field` |
| `areas[].action` | `dashboard.create_action()` |
| `design.font` | `set_default_font()`（`apply_config()` から適用済み） |
| `design` の色 | `draw_*()` の色引数。`@main_color` を実際の色コードへ解決して渡す |
| `design.spacing` | `build_report(content_style=)`。`wide` は `margin 8 / padding 16`、`narrow` は `margin 4 / padding 8` |
| `design.filter_apply_button` | `build_report(filter_apply_button=)` |

**1 段にグラフとフィルターを混ぜられる点が受け手に無かったため、`build_report()` の
区分値を項目ごとへ移した（2026-09-07）。** それ以外の食い違いは、ヘッダー文言の引数追加と
用語の統一で解消した。

## 実装済みと未実装の境界

受け手は `TwbWorkbook.apply_config()`。**画面が出す節はすべて届く（2026-09-07）。**

| 出力 | 受け手 |
|---|---|
| `datasources.*.folders` | `apply_field_config()` へ渡す |
| `datasources.*.renames` | フィールドを解決して `field.update(name=)`。フォルダへは入れない |
| `datasources.*.calculations` | `create_calculated_field()`、同名があれば `update()` で上書き |
| `design.font` | `set_default_font()` |
| `design` の色・余白・適用ボタン | **`dashboard` を組むときに使う。** 単独では届かないので、`dashboard` が無い設定では名前をログに出して読み飛ばす |
| `dashboard` | `draw_*()` でシートを作り、`build_report()` で並べ、`create_action()` を張る |

受け手が無い節はエラーにせず、名前を警告ログへ出して読み飛ばす。画面は常に全節を
出力するため、エラーにすると出力した YAML がそのまま使えなくなる。

### ダッシュボードの組み立ては 2 段

画面の 1 エリア = 1 シートで、`build_report()` は**既にあるシートを並べるだけ**。

```
1 段目  areas[].chart と params から draw_*() でシートを作る
        フィルターのエリアは set_filter() で登録する（全シートを作ってから）
2 段目  rows から struct を組み立てて build_report() へ渡す
3 段目  areas[].action から create_action() を張る
```

段の名前が空、または重複しているときは `段1` / `段2` を割り当てる。`struct` のキーは
一意でなければならないため。

### 2 周方式で同じ YAML を 2 度通すとき

`calculations` は同名があれば式・データ型・役割・フォルダを上書きする。2 度目に
「既に存在する」で止まると往復が回らないため。

`folders` は「元カラム名 → 表示名」なので、**適用済みの `.twb` へ同じものをもう一度
渡すと元カラム名が見つからず `NotFoundError` になる。** 2 周目は焼き直した `.twb` から
画面を出し直し、YAML も作り直すのが正しい手順。

### 役割から決まるもの

`role: dimension` は不連続（`discrete=True`）、`role: measure` は連続として作る。
画面では指定しない。
