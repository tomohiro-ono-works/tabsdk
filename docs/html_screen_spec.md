# 設定画面 HTML の設計書

- 作成日: 2026-09-06
- 対象: `twbpatch/html_export.py` と `TwbWorkbook.export_html()`
- 位置づけ: **実装済みの画面の仕様書。** 作業計画は `docs/tasks/J_html_config.md`

## 目的

ダッシュボードを組む前に、データソースのフィールドを調べて Python コードへ手で書き写す作業を
なくす。ワークブックの内容を画面に出し、**画面で設定して設定ファイルを吐かせる。**

## 全体像

```
1周目  wb.export_html("config.html")
         → データソースタブで表示名・フォルダ・計算フィールドを設定
         → データソースタブの「設定 YAML をダウンロード」
         → wb.apply_config() で .twb へ適用して保存
2周目  適用後の .twb から export_html() し直す
         → 計算フィールドが実在フィールドとして候補に出る
         → ダッシュボードタブ / KPI ツリータブで画面を組む
         → そのタブの「設定 YAML をダウンロード」
         → wb.apply_config() で .twb へ適用して保存
```

**2 周に分ける理由**: 計算フィールドは 1 周目で `.twb` に焼くまで存在しない。
焼いてしまえば役割もデータ型も確定するので、**式から役割を推測する処理が要らない。**

## API

```python
TwbWorkbook.export_html(
    path,                      # 出力先
    *,
    title="twbpatch 設定",     # 画面と <title> に出す名前
    overwrite=False,           # 既存ファイルがあれば FileExistsError
    config=None,               # 設定 YAML（パスか辞書）。画面へ戻す（下記）
) -> Path
```

仕様 §2.0 の **API 方式**。`serialize_workbook()` の結果を HTML へ整形するだけで、
クラス方式の上にしか建てていない。§6.14 の一覧に載る。

### 設定 YAML から画面を戻す（2026-09-21 追加）

`config=` に設定 YAML を渡すと、**`.twb` に残らない 3 節を画面の初期値へ戻す。**

| 節 | 戻すもの |
|---|---|
| `design` | フォント / 各色 / 余白 / フィルターの「適用」ボタン |
| `dashboard` | 名前・大きさ・ヘッダー（色はデザインルール参照のまま）・段とエリア全部 |
| `kpi_tree` | 名前・データソース・親ノードの位置・ツリー全体 |

`datasources` は戻さない。**`apply_config()` で `.twb` に焼かれるので、そちらから
読み直す**（二重に持つと食い違う）。YAML は `config-data` の `<script>` へ
埋め込み、`restoreDesign()` / `restoreDashboard()` / `restoreKpiTree()` が入力欄と
状態へ書き戻す。データソースは名前で持っているので、画面の添字へ引き直す。

これを使うのが bat の 2 番（`scripts/02_apply_config_html.py`）で、
`apply_config()` を当ててから同じ YAML を渡して画面を作り直す。

**最初の `renderRows()` は KPI ツリーのスクリプトの末尾で呼ぶ。** 段の描画は
シート名の重複チェックで KPI ツリーの状態（`const KT`）を見るため、
ダッシュボード側で呼ぶと「Cannot access 'KT' before initialization」になる。

## 実装の制約

- **外部依存を増やさない。** 依存は `lxml` と `PyYAML` のみ。CSS と JavaScript は
  インラインで埋め込み、CDN もテンプレートエンジンも使わない。**オフラインで開ける。**
- **サーバを立てない。** 設定ファイルはブラウザのダウンロードで受け渡す。
- 出力した HTML は単体で完結し、他のファイルを参照しない。
- **ブラウザ側で `.twb` / `.twbx` を読ませない。** 技術的には可能（`DOMParser` と
  `DecompressionStream("deflate-raw")`）だが、フィールドの取り出しは接続の
  `metadata-record` との突き合わせを含むため、JavaScript へ写すと Python と
  二重管理になってずれる。**解析は Python 側に置く。**

## 画面の構成

固定ヘッダー（`position: sticky`）に 4 つのタブ、その右にワークブック名と件数が並ぶ。
**「設定 YAML をダウンロード」はタブごとに右上に置き、そのタブで使う節だけを出す**（2026-09-14、下の「出力する設定ファイル」）。

| タブ | 中身 | ダウンロードで出す節 |
|---|---|---|
| 全体（デザインルール） | フォント・色・余白・フィルターの適用ボタン | 無し（ダッシュボード・KPI ツリーのファイルに入る） |
| データソース | リネーム・フォルダ設定 / 計算フィールド | `datasources` |
| ダッシュボード | 新規ダッシュボードの構成 | `design` + `datasources` + `dashboard` |
| KPI ツリー | KPI カードを親子関係のツリーに並べた新規ダッシュボード | `design` + `datasources` + `kpi_tree` |

## 全体（デザインルール）タブ

ワークブック全体に効く書式。**データソース側でもダッシュボード側でもない第 3 の対象。**

| 項目 | 入力 | Python 側の受け手 |
|---|---|---|
| プリセット | 選択式（モスグリーン / ネオン・ノワール / ソメイヨシノ） | 画面だけの入力。選ぶと下の全項目へ反映する（下記） |
| フォント | 選択式（20 件） | `set_default_font()` |
| メインカラー | 色見本 + 16 進表記 | **なし** |
| サブカラー①②③ | 同上 | **なし**（③は 2026-09-21 追加） |
| 追加アクセント | 同上（既定は空。空なら YAML に出さない） | **なし**。`@accent_color` で参照できる（2026-09-25 追加。ソメイヨシノの緑） |
| 文字色①② | 同上 | **なし**（`set_default_font()` は `font-family` しか書かない）。2026-09-21 に `text_color` を ①② の 2 つへ分けた |
| 背景色 | 同上（既定 `#f5f5f5`） | `build_report(content_style=)` / `build_kpi_tree(content_style=)` の背景色。ダッシュボードの台紙（グラフの後ろの地）と、余りを埋める空きゾーンの色になる（2026-09-21 追加。それまでライブラリ側の固定値だった） |
| 枠線の色 | 同上（既定は空） | `build_report(border_color=)` / `build_kpi_tree(border_color=)`。**色を入れたときだけ**ゾーンに枠線（solid・幅 1）を引く（2026-09-21 追加） |
| ヒートマップ：最小値/中間/最大値の色 | 同上（既定 `#2166ac` / `#f7f7f7` / `#b2182b`） | **なし**。`draw_crosstab` の `min_color`/`mid_color`/`max_color` から `@min_color` 等で参照する専用（2026-09-12 追加） |
| フィルターに「適用」ボタン | チェック | **なし**。XML 上の表現も未調査 |
| 余白 | 広い / 狭い（**既定は狭い**、2026-09-21 に「多め / 少なめ」から改称し既定を変更） | `build_report()` の `content_style` に相当 |

**プリセット**（2026-09-25）。`DESIGN_PRESETS`（`html_export.py`）に 3 種を持ち、選ぶと
フォント・色・追加アクセント・枠線・適用ボタン・余白の**全項目を置き換える**。
反映後は項目ごとに自由に変えられる（プリセットは出発点で、選び直すまで保持しない）。
空の値（追加アクセントや枠線が無いプリセット）も反映し、前の値を残さない。
プリセットの表に無い項目は次のように当てた。

- フォントは CSS の並び（`Arial, sans-serif`）の先頭だけ（Tableau は名前を 1 つしか受けない）。`Poppins` は候補へ足した
- 「適用」ボタンの色は受け皿が無い（チェックだけ）ので反映せず、3 種とも「入れる」にチェックを入れる
- 余白 `24px` は「広い」、指定の無いモスグリーンは既定の「狭い」

フォント候補は `FONT_CHOICES`。Tableau Desktop の既定（Tableau Book / Medium / Regular）と
Windows・macOS の日本語標準フォントを並べる。

色見本（`input[type=color]`）と 16 進表記は双方向に同期する。

## データソースタブ

データソースを選ぶと、その内容が 2 つの表に出る。**片方を開くともう片方が閉じる**
排他アコーディオン。データソースを切り替えても編集内容は保持する（`EDITS`）。

### セル状の表の共通仕様

| 操作 | 動き |
|---|---|
| 範囲選択 | ドラッグ / Shift+クリック / Shift+矢印 |
| コピー | Ctrl+C で選択範囲を TSV に。Excel へそのまま貼れる |
| 貼り付け | Ctrl+V で選択位置を左上に複数セル展開 |
| 消去 | Delete / Backspace（読み取り専用セルは変えない） |
| セルを選ぶ | クリック（1回目）。枠線が付くだけでキャレットは入らない |
| テキストを編集する | 選んだセルをもう一度クリック / F2 / 文字キー（置き換えて編集） |
| 編集をやめる | Ctrl+Enter または Escape（同じセルの選択に戻る） |
| セルの移動 | 矢印 / Enter / Tab（**選択中のみ**。編集中の矢印はセル内のキャレット移動） |
| セル内改行 | 編集中の Enter（Alt+Enter も同じ） |
| 元に戻す・やり直し | Ctrl+Z / Ctrl+Y（Ctrl+Shift+Z） |

**1クリック目は選択、2クリック目で編集**（2026-09-13 変更、Excel に合わせた）。
以前はセルが常に `contenteditable` で、1クリックで即キャレットが入っていた。
セルは既定では編集不可にし、**「編集できるセル」は `data-edit` 属性**で表す
（`editableCell()` / `readonlyCell()`）。`beginEdit()` がそのときだけ
`contenteditable` を付け、`endEdit()` が外す。したがって JS 側では
`isContentEditable` は「いま編集中か」、`isEditable()` は「編集できるセルか」を
意味する。選択中も矢印移動とコピーを効かせるため、セルには `tabindex="-1"` を
付けてフォーカスできるようにしてある。選んだセルは `td.active` の枠線、編集中の
セルは `td[contenteditable]` の背景色で見分ける。

**編集中はセルの外へ出さない**（2026-09-13 修正）。矢印キーはすべてセル内の
キャレット移動にする（上下は複数行の式の1つ上/下の行へ）。以前は編集中でも
上下キーが隣の行のセルへ飛んでしまい、複数行の式を直せなかった。編集を終えるのは
Ctrl+Enter（同じセルの選択へ戻る。そこから矢印でセルを移動する）と Escape。
Tab だけは Excel と同じく確定して隣のセルへ動く。

**編集中の Enter はセル内改行、確定は Ctrl+Enter**（2026-09-13 変更）。当初は
Excel に合わせて Alt+Enter だけを改行にしていたが、この表で複数行になるのは
主に式なので、書きやすさを採って入れ替えた。Alt+Enter は Excel の指の記憶に
合わせた別名として残してある。**選んでいるだけのとき（編集中でない）の Enter は
従来どおり1つ下のセルへ移動**するので、選択中の操作感は変わらない。

これに伴う周辺の調整:

- **コピーは1セルでも効く**。以前は範囲選択のときだけ自前でコピーし、1セルは
  キャレットが入っていたのでブラウザ既定に任せていた。選択モードではキャレットが
  無いので、選択があれば1セルでも自前でコピーする。編集中はセル内の文字選択を
  そのままコピーさせる
- **編集中の貼り付けはキャレット位置へ素のテキストで差し込む**。ブラウザ既定に
  任せると `<div>` や `<br>` が入り、`textContent` で読む側が壊れるため
- **候補ポップアップを閉じる処理は capture フェーズ**。選択が mousedown の中で
  `cell.focus()` を呼ぶようになり、その focus で開いたポップアップを、同じ
  クリックの続きで流れてくる「外側クリックで閉じる」処理が即座に閉じてしまって
  いた（1クリックでは候補が出ない）

**セル内改行は Alt+Enter**（2026-09-13 追加。主に式の複数行入力向け）。素の
`"\n"` テキストノードを挿入する（`<br>` にしない）。`textContent` は `<br>` を
無視して前後を連結してしまい、`captureInto()` など読み取り側で改行が消える
（式の複数行が1行に潰れる）ため。`white-space: pre-wrap` を
`td[contenteditable]` に指定し、素の改行を画面上でも折り返して見せる。
**コピー時、セル内の改行は行区切りの `\n` と区別しない**（既知の制限）。範囲コピー
に改行入りのセルが混ざると、貼り付け時に行がずれる可能性がある。

**`contenteditable` の既定の undo は使わない。** 貼り付けや行の増減を追えず表が壊れるため、
既定動作を止めて `tbody` のスナップショットを 100 手まで保持する自前の履歴に置き換えた。
連続入力は 500ms の無操作かフォーカスを外した時点で 1 手にまとめる。

**表計算ライブラリは使えない**（外部依存を増やさない制約）ので、上記はすべて自前実装。

**列幅はドラッグで変更できる**（2026-09-13 追加）。`table-layout: fixed` にし、
`<colgroup>` の `<col>` 幅を書き換える（`enableColumnResize()`）。最後の列は
残り幅を埋めるので境界の対象にしない。`<thead>` はデータの再描画
（`renderTables()`）では作り直さないため、ページ読み込み時に1回つければ持続する。

**判定は th 内の小さなつまみ要素ではなく、表全体への mousedown/mousemove で
「クリック位置が列境界の x 座標に近いか」を見る方式**（2026-09-13、2段階で
修正）。最初は `<th>` の右端に `.col-resize-handle` という子要素を置き、そこへの
ドラッグだけを拾っていたが、当たり判定が `<th>` の高さ（ヘッダー行1行ぶん）に
限られ、見た目の縦線（表の全行にまたがる）のごく一部でしかつかめずシビアだと
いう指摘を受けた。最終形では `boundaryAt(clientX)` が各列境界の x 座標との距離
（`COLUMN_RESIZE_HIT_ZONE`、左右10px。2026-09-13 に6pxから拡大）だけを見るため、
ヘッダーでも本文のどの行
でも、縦線の全長どこを押しても掴める。`enableGrid()` のセル選択
（`event.target.closest("td")` で始まる、bubble フェーズ）より確実に先に判定
できるよう、`enableColumnResize()` の mousedown は capture フェーズで登録し、
境界にヒットしたら `stopImmediatePropagation()` でセル選択を起こさせない。

境界 i のドラッグは **col[i] と col[i+1] の幅の合計を変えず、2列の間だけで
やり取りする**（2026-09-13 修正）。当初は動かした列だけを % から px 固定に
変えていたが、他の列は % のまま残るため、`table-layout: fixed` が「列幅の合計を
表の幅に一致させる」ために動かしていない列（特に左隣）まで勝手に再配分して
しまう実害があった。`enableColumnResize()` は全列の幅を実測 px へ固定してから、
以降は隣接する2列間だけで幅を移し替える。最小幅（`COLUMN_RESIZE_MIN_WIDTH`）は
動かす側・動かされる側の両方に効くので、広げすぎて隣の列を潰すこともできない。
`<col>` は非表示要素で `getBoundingClientRect()` が使えないため、対応する `<th>`
の実測幅を使う。

**「全列を実測 px へ固定する」処理はドラッグを始めるたびに呼び直す**
（`freezeAllColumnWidths()`、2026-09-13 修正）。当初はページ読み込み時に1回
だけ呼んでいたが、計算フィールド表（`#calc-table`）はアコーディオンが既定で
折りたたまれている（`.acc-body { display: none; }`）ため、その間は
`getBoundingClientRect()` が 0 を返し、全列が幅0pxのまま固定されてしまった。
後で列を1つ動かすと「指定した合計（実質0）が表の幅に足りない分」の帳尻合わせで
他の列が一気に広がって壊れる実害があった。表が畳まれた状態で固定を1回きりにせず、
実際にドラッグを始めた（＝表が確実に見えている）タイミングで毎回撮り直すことで
解決した。

#### リネーム・フォルダ・階層を AI に考えてもらう

**「選んだ行から AI 用プロンプトを作る」ボタン**（2026-09-21 追加）。選んだ行の
元カラム / データ型 / 役割 を**二重縦棒（||）区切り**にしてプロンプトへ差し込み、
ダイアログに出す。入力も出力も同じ区切りにしてある。タブはチャットへ貼ると潰れ、
「商品 ID」のように値へ空白が入る名前と区別できなくなるため。
「クリップボードにコピー」で写して、生成 AI へ貼る。

行の選び方は次の順に見る。

1. **Ctrl+クリックで拾った行**（薄い青。行のどこを押してもよい）。表の範囲選択は
   長方形なので、飛び飛びの行はこちらで選ぶ。**Shift+クリック**は直前に拾った行から
   そこまでをまとめて拾う（既に拾った行があるときだけ。無いときは今までどおり
   セルの範囲選択）。「行の選択を解除」で全部外す
2. 表で範囲選択した行
3. どちらも無ければ、絞り込みで残っている全行

拾った行は元カラム名で覚えるので、表を描き直しても残る。

- プロンプトの本文は `html_export.py` の `_FIELD_PROMPT`。命名・フォルダ・階層の決め方を
  この画面の規則（フォルダ名は `01_売上指標` の形、階層は 2 つ以上・同じフォルダ・
  フィールドと別名）に合わせて書いてある
- `twbpatch/prompt_rules/` 直下の UTF-8 `.md` を HTML 生成時にファイル名順で読み、
  ファイル名をチェックボックスに表示する。本文は生成 HTML 内へ安全に埋め込み、
  `file://` でも動作する。サブフォルダは対象外。ファイルを変更した場合は HTML を再生成する
- 初期状態では `00-common-rules.md` のみチェック済み。顧客・商品などの分類は利用者が手動で選び、
  Tableau のデータソース名から自動判定しない。チェック済みファイルの本文を、
  テキストエリアの境界付き `# 参照ルール` 欄へファイル名付きで加える
- チェックを変更すると参照ルール欄だけを再構成し、外したファイルの本文を削除する。
  チェックがゼロなら欄ごと削除する。欄の外の手編集は保ち、欄内の手編集は再構成時に置き換わる。
  境界が変更された場合はテキストを推測で書き換えず、プロンプトの再生成を案内する
- リネーム用と計算フィールド用のチェック状態は別々に保つ。各フォルダが空ならその用途の
  チェックボックスを表示せず、基礎プロンプトは使える。MD を読めない場合は HTML 生成を止め、
  対象ファイル名入りのエラーを返す
- AI に返させるのは**入力と同じ行数・同じ並びの 4 列**
  （元カラム / リネーム後名称 / フォルダ / 階層）で、**区切りは半角の縦棒 2 つ（||）**
- **1 列目が表にある元カラム名と全部そろっていれば、貼り付け位置ではなく名前で行を合わせる**
  （2026-09-21）。飛び飛びに選んだ行でも、並べ替えた後でも、そのまま貼れる。
  2 列目以降は**選んでいたセルの列から順に**入るので、フォルダの列を選んで
  `Region||03_地理` のように 2 列だけ貼れば、フォルダだけを書き換えられる。
  1 列目が表に無い名前なら、今までどおり貼り付け位置から順に入る
- **貼り付けの区切りはタブが優先、無ければ二重縦棒、それも無ければ縦棒**（2026-09-21）。
  Excel やスプレッドシートからのコピーはタブなので従来どおり。生成 AI の返事はタブが落ちて届く
  ことが多く、「商品 ID」のように値へ空白が入る名前があるため、空白では区切れない。二重縦棒に
  しているのは、「売上|当年」のように値へ縦棒が入る名前とぶつからないため。Markdown の表で
  返ってきたときのために、行頭行末の `|` と区切り行（`---`）は落とす。末尾の区切りは落とさない
  （3 列目が空の行を 2 列と読み違えないため）
- 階層の順は行の並びで決まるので、AI の結果が粗い → 細かいの順になっていなければ
  掴み手（⠿）で並べ替える
- `file://` で開くと `navigator.clipboard` が使えないことがあるため、失敗したら
  テキストを選択して `execCommand("copy")` へ落とす

**計算フィールドの表にも同じボタンがある**（「AI 用プロンプトを作る」、2026-09-21）。
基礎本文は `_CALC_PROMPT`。リネーム・フォルダ設定で選んだフィールドと、いま計算フィールドの表に
入っている名前を一覧にして渡し、返ってくる 5 列（名前 / 式 / フォルダ / データ型 / 役割）を
この表の左上へ貼り付ける。`twbpatch/calc_prompt_rules/` 直下の UTF-8 `.md` を
計算専用の参照ルールとしてファイル名順に表示する。`00-calculation-rules.md` は初期チェック済み。
IIF で文字列を絞る式、集計後の割り算、ゼロ除算、二重集計の回避などはこの MD に置く。
計算用チェックを変えたら計算用プロンプトの `# 参照ルール` 欄だけを更新する。
リネーム用の MD はここに混ぜず、5 列・`||` 区切りの出力契約はチェック状態に関係なく維持する。
ダイアログは 2 つのボタンで使い回し、「# 作りたい指標」を書き足せるよう入力できるままにする。

#### 階層（ドリルダウン）

**階層は「階層」列だけで表す**（2026-09-21 追加）。同じ階層名を書いた行がその階層の
フィールドになり、**表の行の並びがそのままドリルの順**になる。階層のフォルダは、その
階層の行の「フォルダ」列から決まる。つまり画面は

```
フォルダ
  階層なしフィールド
  階層
    階層に入れたフィールド
```

という木を、1 列と行の並びだけで表す。`.twb` の XML はこれと別の形（階層は
`drill-paths`、フォルダには `type="drillpath"` の項目として入り、階層に入れた
フィールドはフォルダの単独項目ではなくなる）で、その変換はライブラリが行う。

**階層の順は行をドラッグして変える**（2026-09-21）。行の並べ替えは `.twb` のフィールドの
並び順を変えるものではなく、階層の順を決めるためだけに使う。

`.twb` に既にある階層は読み込んで「階層」列に入れ、その行を階層の順に並べ替える。
階層に入っているフィールドの「フォルダ」列には、**階層が置かれているフォルダ**を出す。

ダウンロード前の検証で止めるもの。

- 階層のフィールドが 2 つ未満
- 同じ階層の行でフォルダがそろっていない
- 階層名と同じ表示名のフィールドがある

**フォルダが「フォルダ未指定」の行は `renames`、それ以外は `folders` へ出力する**
（2026-09-08 決定）。`apply_field_config()` の設定形式は「フォルダ名 → {元カラム名: 表示名}」
の3階層固定でフォルダなしを表現できないため、フォルダに入れずに改名だけしたい場合の
入口を別セクションにした。表示名が空の行はどちらにも出力しない。

画面側で検証する（`apply_field_config()` が例外にする条件を出力前に防ぐ）。**フォルダが
「フォルダ未指定」の行はこの検証の対象外**（フォルダに割り当てないため）。

- フォルダを指定した行で表示名が空 → セルを赤くしてエラー欄に出す
- 同じフィールドを 2 つのフォルダに割り当て → 同上

### 計算フィールド

列は 名前 / 式 / フォルダ / データ型 / 役割（2026-09-12 順序変更）。既存の計算フィールドを
初期表示し、空行を 3 行足す。「行を追加」と「選択行を削除」。貼り付けで行が足りなければ自動で増える。

**役割とデータ型は自動判定しない。** `create_calculated_field()` は `datatype="real"` /
`role="measure"` の固定既定を持つだけで、式を読んでいない。式から戻り値の型を推論するには
Tableau の関数を一通り実装することになるため、**画面で入力してもらう。**

フォルダ・データ型・役割はいずれもフォーカス時に候補ポップアップが出る（自由入力・
コピー貼り付けは維持）。

- **フォルダ**: リネーム・フォルダ設定タブと同じ候補（入力済みフォルダ名＋「フォルダ未指定」）。
  検証はしない。「フォルダ未指定」の行は YAML 出力時に `folder` キーを出さない
- **データ型**: `string` / `integer` / `real` / `boolean` / `date` / `datetime`
- **役割**: `measure` / `dimension`

データ型・役割は自由入力を許すが、候補にない文字列を入れるとセルが赤くなり、
「設定 YAML をダウンロード」を押すとエラー欄に出て止まる。

**式の `[フィールド名]` は参照先の有無を見る**（2026-09-21 追加）。無ければ式のセルが
赤くなり、エラー欄に「無いフィールドを参照しています ([○○])」と出る。使える名前は
**リネーム後の名前**（未入力なら元の名前）と、この表で定義する計算フィールドの名前。
受け手はリネームを当ててから式を作るので、リネーム前の名前は使えない。リネームを
直すと判定もその場で見直す。文字列の中に `[` `]` が入っている式は誤判定になりうるが、
実在しない名前に早く気づける方を採る。

## ダッシュボードタブ

**新規に組む専用。** 既存ダッシュボードの読み込み・編集はしない。ただし
**設定 YAML からは戻せる**（下記「設定 YAML から画面を戻す」）。

```
ダッシュボード   名前 / 幅 / 高さ
ヘッダー         タイトル / 高さ / 背景色 / 文字色（色はデザインルールを参照できる）
ボディ（縦段組）
  段             名前 / 高さ / 幅を均等割り / 折り畳み / 並べ替え / 削除
    エリア       グラフ または フィルター
```

**名称と色には既定を入れる**（2026-09-21）。ヘッダータイトルはダッシュボード名と同じ
「ダッシュボード」、段の名前は追加した順に「1段目」「2段目」（Tableau のレイアウト
ツリーに出るコンテナ名になる。並べ替えても付け直さない）。ヘッダーの背景色と文字色は
グラフの色と同じ `colorControl` で、既定は背景＝メインカラー参照、文字＝背景色参照。
文字色①②など他の色や、個別の色コードも選べる。参照は `@キー` のまま YAML へ出し、
受け手が解決する。

### 段とエリア

- 段もエリアも掴み手（⠿）でドラッグして並べ替える。**エリアは別の段へも移せる。**
  落とす位置は青い線で示す
- 掴み手を押したときだけ `draggable` を立てる。カード全体を常時 `draggable` にすると
  入力欄の文字選択ができなくなるため
- 段は折り畳める。畳むと見出しに「エリア N 件」だけが残る
- エリアの表示幅は **360px 固定**で、段の中を横スクロールする
- px の入力（ダッシュボードの幅・高さ、エリアの幅）は 10 刻み。**段の高さだけ 60 刻み**
  （2026-09-21 に 10 から変更）。既定は段の高さ 300、エリアの幅 600
- **段ごとに「幅を均等割り」を選ぶ**（2026-09-21 追加、既定は入れる）。入れると
  YAML に `distribute_evenly: true` が出て、Tableau の「均等に配布」の段になる。
  この段ではエリアの幅 (px) を書いても Tableau が読まないので、入力欄を使えなくし、
  YAML にも `width` を書かない。外すと指定した px がそのまま幅になり、余りは段の
  末尾の空きゾーンが吸う
- エリアは「複製」ボタン（⧉）で同じ段の直後にコピーできる（2026-09-08 追加）。
  `params` / `action` を含めて複製し、シート名はそのままコピーする（重複チェックは
  シート名生成ボタン側で行うため、複製時点では変えない）

### エリアの中身

| 種別 | 入力 |
|---|---|
| グラフ | シート名 / グラフ種類 / データソース / グラフパラメータ |
| フィルター | データソース / 種類（ディメンション / メジャー / すべて） / フィールド |

**シート名が空、または他と重複していると入力欄を薄い赤にする**（2026-09-21）。
判定はダウンロード前の検証と同じで、`.twb` の既存シート・ダッシュボードタブ・
KPI ツリータブのシート名を見る。

**ただし、読み込んだ設定 YAML が作るシート・ダッシュボードは「既にある」に数えない**
（2026-09-21 修正）。`config=` で画面を戻すとき（bat の 2 番）、その YAML は既に
`.twb` へ適用されているので、戻した段のシート名が軒並み重複扱いになっていた。
同じ YAML をもう一度適用すれば作り直されるので、重複ではない
（`existingSheetNames()` が `configSheetNames()` を差し引く）。

**シート名は右隣のボタン（✎）でグラフ種類と選んだ項目から自動生成できる**（2026-09-08
追加、手入力も可）。`{短縮ラベル}|{フィールド名}`（複数は `×` で連結）の形。

**候補の多いプルダウンは、押すと検索欄と候補一覧が下に開く**（2026-09-21）。
閉じているときは選択中の値だけを出し、押すと上に検索欄、下に候補一覧が並ぶ。
打った文字を含む候補だけが残り、選ぶと閉じる。外側を押すか Esc でも閉じる。
値は隠した `<select>` が持つので、呼び出し側は今までどおり `select.value` と
change イベントで扱う（`searchable()`）。**フィールドの候補はフォルダごとに
見出しを付けて並べる**（`<optgroup>` から作る。絞り込みで中身が残らないフォルダは
見出しごと出さない）。

一覧は**開いている間だけ `<body>` の直下へ預け**、画面に対して固定で置く
（重なり順は 90。モーダルの 100 より下、ほかより上）。エリアの箱は横スクロール用に
`overflow-x: auto` で、これは縦もスクロールする設定になるため、中に置いたままだと
一覧が枠で切れ、段に縦スクロールバーまで生えていた。閉じると元の場所へ戻し、
段を描き直すときも閉じる（`<body>` に取り残さないため）。

候補が `COMBO_SEARCH_MIN`（6）以下のプルダウン（グラフ / フィルターの区分、グラフ種類、
フィルターの種類、データソースなど）は探す必要が無いので、素の `<select>` のまま。

> はじめは `<select>` を隠して `<input list>` + `<datalist>` の一体型にしたが、
> 選択中の値が入力欄に残るせいで Chrome の datalist がその値を含む候補しか出さず、
> 候補 25 件のフィールドでも 1 件しか開けなかった。次に素の `<select>` の上へ検索欄を
> 常に置いたが、使わない欄まで場所を取るため、押したときだけ開く形にした。

**KPI カードはモードで入力欄が変わる**（2026-09-21 追加）。「モード」を選ぶと、
そのモードで使う引数だけを出す（`CARD_MODE_PARAMS`）。

| モード | 出る入力 |
|---|---|
| サブ指標モード（既定） | サブメジャー |
| 予実比較モード | 予算比指標 / 境界値（既定 1.0）/ 達成時の色 / 未達時の色 |

モードと、そのモードの主役（予実比較なら予算比指標）は詳細設定に畳まず前に出す。
**選んでいないモードの引数は YAML にも書かない。** 両方書くと受け手が
「budget mode does not take sub_metric」で止まるため。全部の引数を並べていた頃の
YAML のために、受け手（`config_apply`）でも使わない方を落とす。

**数の引数は文字列で出る**（`opacity: "0.4"`、`budget_threshold: "1"`）。画面の入力欄が
文字列を返すため。受け手が `draw_*()` の注釈を見て数へ戻す（2026-09-21。それまで
`draw_quadrant` の `opacity` などが「must be a number」で止まっていた）。

**選択肢の並び順は `_CHART_LABELS` の順**（2026-09-21。よく使う順に固定した。
以前はメソッド名の名前順だった）。下の表もその順に並べる。

| グラフ | 短縮ラベル | 使うフィールド |
|---|---|---|
| KPIカード (`draw_card`) | スコア | `main_metric` |
| 棒グラフ (`draw_bar`) | 棒 | `item`, `metric` |
| 帳票 (`draw_sheet`) | 帳票 | `items`（先頭2件） |
| クロス集計（ヒートマップ） (`draw_crosstab`) | クロス | `x_item`, `y_item` |
| 散布図（四象限） (`draw_quadrant`) | 象限 | `x_metric`, `y_metric` |
| ウォーターフォール (`build_waterfall`) | 滝 | `metrics`（先頭2件） |

未選択のフィールドは無視して、選ばれた分だけで組む。同名シートが既にあれば
末尾に「 (2)」「 (3)」…を付ける（2026-09-14 に `_2` から変更）。重複を見る相手は、ダッシュボードタブ・
KPI ツリータブのシート名と `.twb` に既にあるシート。エリアを複製したときも同じ規則で付ける。
手で入力した名前の重複はダウンロード前の検証で止める。

区分値は `worksheet` / `filter`。**`build_report()` の項目の区分値と同じ言葉**を使う
（画面の表示は「グラフ」「フィルター」のまま）。1 つの段に混ぜてよい。

### インフォメーションを追加（2026-09-23 追加）

グラフのエリア（`kind="worksheet"`。`draw_info` 自体は除く）と、KPI ツリーのノードに
「インフォメーションを追加」チェックボックスを出す。チェックすると `draw_info()` の
入力（本文・アイコン・見出し・色）が現れる。アイコンの選択肢と各入力の既定値は
`DRAW_SPECS["draw_info"]` からそのまま読み、画面側で二重に持たない。

- **本文は複数行のテキストエリア。** `_param_kind()` は `text` という名前だけの特例で
  `"textarea"` を返す（`draw.py` に他に `text` という引数が無いことを確認して安全に判定）
- ダウンロード前の検証で、チェックが入っているのに本文が空だと止める
  （そのままだと受け手の `draw_info()` が `ValueError` になるため）
- エリア・ノードの複製（⧉）は `info` もコピーする

**受け手（`config_apply.py`）は `build_report()` / `build_kpi_tree()` の後で処理する。**
対象シートが実際にどこへ Tiled 配置されるかは、レイアウトを組み終えるまで px 位置が
決まらないため。`_apply_info()` が対象シートのゾーン（`TwbDashboardZone.x`/`.y`/`.width`）を
`dashboard.get_zones()` から探し、その**右上へ 30px 四方・余白 4px** で
`add_floating_worksheet()`（**浮動**配置、既存 API）を使って重ねる。ワークシート名は
固定で `info|<対象シート名>`。

```yaml
areas:
  - kind: worksheet
    sheet: 売上推移
    chart: draw_bar
    params: {...}
    info:
      text: "この指標は前月末時点の実績です。"
      icon: "info"          # "info" / "quest" / "setting" / "attention"
      heading: "説明"        # 省略可、既定 "説明"
      color: "#e15759"      # 省略可、既定は draw_info() の既定色
```

KPI ツリーのノードも同じ `info:` を持てる（`kpi_tree.root` / `children` の各ノード）。

### アクション設定

どちらのエリアもアクションを 1 つ持てる。種類は**フィルターと URL を開くの 2 つ**。
ハイライトは受け手（`dashboard.create_action()`）が無いので画面に出さない。

| 種類 | 入力 |
|---|---|
| フィルター | 対象シート名 / 絞り込むフィールド |
| URL を開く | URL |

**フィールドは必須。** Tableau の「すべてのフィールド」は使わない前提のため
（2026-09-07 決定）、指定なしのフィルターアクションは作れない。
候補はエリアのデータソースのディメンションに絞る。

### グラフパラメータの入力欄は自動生成する

**手で書き写した引数一覧を持たない。** `_draw_specs()` が `TwbWorkbook.draw_*()` の
シグネチャを `inspect` で読み、入力欄の種類を型注釈から決める。

| 型注釈 | 入力欄 |
|---|---|
| `list[FieldInput]` | フィールドの複数選択（チェックボックス付きプルダウン、下記） |
| `FieldInput` | フィールドの選択 |
| 引数名が `_PARAM_CHOICES` にある | プルダウン選択（下記） |
| 名前が `colors`（複数形） | 色見本を4つ並べる（下記） |
| 名前に `color` を含む | 色見本 + デザインルールの参照 |
| `bool` | チェックボックス |
| `float` / `int` | 数値 |
| その他 | テキスト |

`draw.py` に引数が増えれば画面も自動で増える。

**同じ引数名でもグラフで意味が変わるものは表示名を上書きする**（`_CHART_PARAM_LABELS`、
2026-09-21 追加）。散布図の `item` は点 1 つの単位を決めるので「点の粒度」、
棒グラフの `item` は今までどおり「項目」。

**フィールドの候補は引数ごとに役割で絞る**（`_PARAM_ROLES`）。項目はディメンション、
メジャーはメジャー。**帳票（`draw_sheet`）の `items` だけは絞らず、両方選べる**
（2026-09-21。メジャーは受け手が集計してからディメンションとして置く）。

**値が固定の選択肢しかない引数はプルダウンにする**（2026-09-12 追加）。`_PARAM_CHOICES`
に登録した引数だけが対象で、値は API 側のバリデーションと一致させる。

| 引数 | 選択肢 | 対応する関数 |
|---|---|---|
| `item_shelf` | 横棒（行）/ 縦棒（列） | `draw_bar` / `draw_sheet` |

登録が無い自由入力の引数（`date_level` など）は、値の候補が今のところ1つしか無いか
未整理のもの。候補が増え次第 `_PARAM_CHOICES` に追加する。

**色を指定できないグラフには引数を足す**（2026-09-12、`draw_bar` に `bar_color` を追加）。
色付けの必要なグラフに色引数が無ければ、API 側の見落としとして `draw.py` に追加する。

**`draw_quadrant.colors`（4色必要）は単一色ピッカーにしない**（2026-09-12 修正）。
名前に `color` を含むという判定だけだと `colors` も単一色ピッカーになり、4色を
指定する手段が画面から失われる実害バグだった。`colorsControl()` が色見本を4つ
並べ、`area.params.colors` に4要素の配列で保持する。既定値は API 側と同じ
`["#4400FF", "#FF007F", "#00C888", "#CCD500"]`。

**4色ピッカーには象限ラベルを付ける**（2026-09-12 追加）。`draw.py` の
`quadrant_formula` は x/y の中央値との大小比較で `colors[0]`〜`[3]` を
右上・左上・左下・右下の順に固定して割り当てる（`QUADRANT_COLOR_LABELS`）。
ラベルが無いと4つ並んだ色見本のどれがどの象限かわからず、意図と違う配色に
なりやすい。順序を変えるときは `draw.py` 側の割り当てとこのラベル配列を
同時に直す。

**`draw_crosstab` の min/mid/max_color は3つ揃えるかゼロかを検証する**
（2026-09-12 追加、`validateDashboard()`）。`draw.py` 側に同じ制約（3つ未満だと
`ValueError`）があるのに画面は未検証で、2色だけ入れた状態のまま保存できてしまい、
`apply_config()` のエラーで初めて気づく状態だった。

**`draw_crosstab` の min/mid/max_color は既定でデザインルールの3色を参照する**
（2026-09-12 追加）。3つ揃えるかゼロかしか許されない制約があるのに、グラフを
置くたびに3色を手入力させるのは非現実的だった。グラフ種類で「ヒートマップ付き
クロス集計」を選んだ瞬間、`defaultParamsFor()` が `min_color`/`mid_color`/
`max_color` を `@min_color`/`@mid_color`/`@max_color`（デザインルールタブの
ヒートマップ既定3色、既定 `#2166ac` / `#f7f7f7` / `#b2182b`）で自動的に埋める。
グラフ側で「個別に指定」に切り替えれば、そのグラフだけ別の3色にできる
（`_DESIGN_TOKENS` に `min_color`/`mid_color`/`max_color` を追加、`config_apply.py`）。

**画面に出さないもの**

- `datasource` / `name` — エリアの他の欄で指定する
- **`aggregation` / `*_aggregation`** — フィールドの役割とデータ型、それに式の中身が
  分かっていれば `draw.py` の `_auto_metric_aggregation()` が決められる。人が選ぶ必要がない。
  **式の中に集計関数があるものは合計ではなく集計（`agg`）として置く**
  （2026-09-22 に棒グラフも統一。`docs/model_api_spec.md`）
- **`draw_card` の `value_color` / `budget_value_color` /
  `title_background_color`**（2026-09-12, 2026-09-13, 2026-09-22）— 画面では
  `main_color` の1つだけ入力させ、残りは YAML 出力時にデザインルールから当てる
  （`paramsYaml()`）。タイトルの背景は `main_color` をそのまま複製、
  メイン指標の数値は `@text_color_1`（文字色①）、予実比較の率は
  `@text_color_2`（文字色②）。**`draw_card()` 自体は4つの引数を持ったまま**で、
  Python 側は既定値だけを持つ。`budget_value_color` は予実比較モードの引数として
  扱うので、サブ指標モードの YAML には書かない
- **`draw_card` の `vertical_alignment`**（2026-09-13 追加）— 「縦は常に中央で
  よい、選ぶ必要がない」との指摘を受けて画面から外した。API 既定の `"center"`
  のまま渡すので YAML には出さない
- **`draw_sheet` の `item_shelf`**（2026-09-22 追加）— 帳票はメジャーを不連続で
  行へ並べ、棒・色帯の列を横へ足す作りなので、「行」以外に選びようがない。
  **グラフごとに出さない引数は `_CHART_PARAM_SKIP`** に置く（`_DRAW_SKIP` は
  全グラフ共通なので、棒グラフの横棒・縦棒の切り替えまで消えてしまう）

**必須と任意を分ける。** 必須だけ前面に出し、任意は「詳細設定」に畳む。
棒グラフなら前面は項目とメジャーの 2 つだけになる。

**任意でも前に出すものがある**（`frontParams()`）。KPI カードのモード（と予実比較モードの
予算比指標）と、棒グラフの項目。棒グラフの項目は 2026-09-22 に任意（省くと棒 1 本）に
なったが、主役の指定なので畳まない。

**任意のフィールド欄は空の選択肢を「（指定なし）」にする**（2026-09-22）。必須なら
今までどおり「（選ぶ）」。選ばないことが正しい指定になる引数があるため
（`fieldOptions(..., optional)`）。

**棒グラフのサブメジャーと折れ線メジャーは同時に選べる**（2026-09-22）。Tableau の二重軸は
2 軸までだが、3 つそろったときは受け手（`draw_bar()`）が棒の軸をメジャーバリューに
まとめるため、画面では何も止めない。ただしそのときは棒 2 本が同じ太さ・メジャーネームの
配色になり、「棒の色」「サブの棒の色」は効かない（`docs/model_api_spec.md`）。

### フィールドの候補は役割で絞る

`_PARAM_ROLES` が、引数ごとにディメンションとメジャーのどちらを求めるかを持つ。

| 引数 | 候補 |
|---|---|
| 項目 / 横の項目 / 縦の項目 / 順位の区切り | ディメンションのみ |
| メジャー / 主メジャー / 横軸のメジャー / 色のメジャー / 折れ線メジャー など | メジャーのみ |

非表示のフィールドは候補から外す。**データソースそのものを表す擬似フィールド
（`[__tableau_internal_object_id__]` で始まるもの）は画面に出さない**（2026-09-21。改名も
フォルダ分類もできないのに、リネーム・フォルダ設定の表に並んでいた）。`export_json()` は
絞り込まず `.twb` のままを返す。

**フィルターは種類を選んでからフィールドを選ぶ**（2026-09-21）。既定はディメンション。
「すべて」を選べば従来どおり全フィールドから選べる。

**フィールドの候補はフォルダごとに `<optgroup>` でまとめる**（2026-09-12 追加）。
プルダウンは1つのまま、フォルダを見出しにしてフィールドを分類する。フォルダ未指定の
フィールドは最後の optgroup にまとめる。フォルダの並びは五十音順、フォルダ未指定が最後。

**複数選択（`list[FieldInput]`）は `<select multiple>` を使わず、左＝候補・
右＝選択済みのモーダルにする**（2026-09-13、2段階で修正）。まず Ctrl+クリック
でないと複数選べず既定で4行程度しか見えない使いにくさを、チェックボックス付き
プルダウンに置き換えて解消した。しかしチェックボックスの並びは「五十音順の
候補一覧」であって「選んだ順」ではないため、`items`（土台シートの並び順）や
`metrics`（帳票の行順）のように**選んだ順序がそのままシート上の配置順になる**
引数では、並び順を指定する手段が無いという指摘を受けた。

最終形は `openFieldOrderModal()`。左リストに未選択の候補（`groupedFields()` で
フォルダごとにグループ化、単一選択の optgroup と共有）、右リストに選択済みを
**選んだ順に**並べる。左→右のドラッグで追加（ダブルクリックでも追加できる）、
右リスト内のドラッグで並べ替え、右の「×」または右→左のドラッグで外す。
右リスト内の並べ替えは、既存の段・エリアの並べ替え（`moveAreaTo()` などと同じ
「ドロップ位置が要素の上半分か下半分かで前後を決める」方式）に揃えた
（`modalDropTarget()`）。`fieldsCheckControl()` のボタン（選択件数を表示）を
押すとこのモーダルを開く。

**帳票の表示方法は、選択済みの行の中のボタンで選ぶ**（2026-09-22）。並び替えの一覧を
表にすると順番をドラッグで変えられなくなるため、一覧の形は変えず、**行の「×」の手前**に
小さなボタン（`.display-pick`）を置く。

- ボタンを置くのは**メジャーの行だけ**。ディメンションには出さない
- **押すたびに 数値 → 棒 → 色付け と変わる**（3 つから 1 つで、個別の on/off ではない）。
  ボタンの文字が今の状態で、数値以外を選んでいるときは色を付ける
- 選んだ結果は `draw_sheet` の `bar_metrics` / `color_metrics` として、**選択済みの順**で
  書き出す。「数値」は行に出るので、どちらにも入らない
- 外した・並べ替えたときは `renderLists()` が、閉じるときは `closeModal()` が
  書き出しをやり直すので、選択から外れたフィールドの指定は残らない

**色は表示方法ボタンの左に出す**（2026-09-22）。棒を選んだ行は 1 色、色付けを選んだ行は
2 色（薄い側・濃い側）、数値の行は出さない。`bar_colors` / `color_starts` / `color_ends` へ
メジャーと同じ並びで書き出す。この 3 つと `bar_metrics` / `color_metrics` は
**詳細設定には出さない**（同じ指定が 2 か所になり、そちらのモーダルには行内ボタンが
付かないため）。

### 表示はすべて日本語

`_CHART_LABELS` と `_PARAM_LABELS` が `draw_bar` → 棒グラフ、`item` → 項目 のように訳す。
英語名は `title` 属性に残す。**訳し漏れがあると英語名がそのまま画面に出る**ため、
漏れが無いことをテストで固定している。

### 色はデザインルールを参照できる

色の引数は「個別に指定」と「デザインルールのメインカラー / サブカラー①② / 文字色 /
ヒートマップ最小値・中間・最大値の色」を選べる（`DESIGN_TOKENS`）。
参照を選ぶと `@main_color` のような文字列として保存し、色見本にはデザインルールの値を映す。
デザインルール側を変えると即座に反映する。

## KPI ツリータブ

`twbpatch/html_kpi_tree.py` に HTML・CSS・JS を置き、`html_export.py` の差し込み口からつなぐ
（ダッシュボードタブの関数をそのまま使う）。受け手は `apply_config()` の `kpi_tree` 節 →
`build_kpi_tree()`（仕様 §6.14）。画面の形は承認済みの試作（2026-09-13）に合わせた。
経緯と決定は `docs/tasks/I2_kpi_tree.md`。

### 上部の設定

| 項目 | YAML | 補足 |
|---|---|---|
| ダッシュボード名 | `kpi_tree.name` | |
| データソース | `kpi_tree.datasource` | タブで 1 つ。変えると全ノードの項目の選択を消す（確認あり） |
| 親ノードの位置（中央 / 上端） | `kpi_tree.align` | `center` / `top`。**既定は上端。上端ならエッジ（線）を描き、中央なら描かない**（中央ではエッジを描けない） |

**エッジの .hyper は画面でも YAML でも指定しない**（2026-09-15）。受け手が同梱の表を使い、`save()` が .twb の隣へ置く。
ダッシュボードとノードの大きさは持たない。ノードは 横 200 × 縦 150 固定で、ダッシュボードの大きさはツリーの形から決まる。

### ツリーの編集

- 左から右へ展開して描く（生成されるダッシュボードと同じ向き）。親ノードの位置の切り替えは画面の描き方にも効く
- 最初は空。「ルートのノードを作る」から始める
- エッジのふもとの ＋ で子を追加 / × でノードと配下を削除（配下があれば確認）/ ⧉ で配下ごと複製 /
  ⠿ のドラッグでカードの上端・下端へ落とすと兄弟の前後、中央へ落とすと子へ移す。ルートは動かさない
- ノードの中身は**ダッシュボードタブのエリアと同じ入力欄**。グラフ種類は KPI カード固定で、
  入力欄は `DRAW_SPECS["draw_card"]` から `paramControl()` で作る。ノードごとの幅・アクションは持たない
- 縦線は親カードと子カードの中心を実測して引く。タブが非表示のあいだは大きさが 0 なので、タブを開いたときにも引き直す
- 右側に KPI ツリーの節の YAML をその場で表示する

### 名前の重複は画面で番号を付ける

シート名の自動生成（✎）と、エリア・ノードの複製は、重複したら「 (2)」「 (3)」…を付ける（2026-09-14）。
重複を見る相手は、ダッシュボードタブ・KPI ツリータブのシート名と、`.twb` に既にあるシート。
「売上 (2)」を複製すると「売上 (3)」になる。

**受け手（`apply_config()`）では付けない。** 受け手で付けると、同じ YAML を誤って 2 回適用しても
止まらずに黙って増え、アクションの対象シート（名前で指定）もずれるため。

### ダウンロード前の検証

データソースの検証に加えて次を止める。

- ノードが無い / シート名が空 / 主メジャーが未選択
- シート名の重複（ツリーの中・ダッシュボードタブ・`.twb` に既にあるシート）。ダッシュボードタブも同じ検証で KPI ツリーと突き合わせる
- ダッシュボード名が `.twb` に既にある、またはダッシュボードタブ（段があるとき）と同じ
- 上端揃え（エッジを描く）で、1 つの親の下の末端が多すぎる（7 つまで。表の縦位置の上限 13 から決まる）

## 出力する設定ファイル

**タブごとの「設定 YAML をダウンロード」で、そのタブで使う節だけを出す**（2026-09-14）。

| タブ | ファイル名 | 節 |
|---|---|---|
| データソース | `twbpatch_datasources.yaml` | `datasources` |
| ダッシュボード | `twbpatch_dashboard.yaml` | `design` + `datasources` + `dashboard` |
| KPI ツリー | `twbpatch_kpi_tree.yaml` | `design` + `datasources` + `kpi_tree` |

以前はナビ右端の 1 つで全タブを 1 ファイルに束ねていた。ダッシュボードタブを使わなくても `dashboard:` 節
（段 0）が出て、適用すると空のダッシュボードが増えていたため分けた。デザインルールは色の参照（`@main_color`）と
余白に要るので、ダッシュボードと KPI ツリーのファイルに入れる。データソースの節は 2 回適用しても上書きになるので
（下の「2 周方式で同じ YAML を 2 度通すとき」）、ダッシュボード用と KPI ツリー用を続けて同じ `.twb` に適用してよい。
名前がぶつからなければダッシュボードが 2 つできる。

下は全節を並べた例。実際のファイルは上の表の組み合わせになる。

```yaml
# twbpatch 設定ファイル（design / datasources / dashboard）
# 受け手: wb.apply_config() がこのファイルを読んで .twb へ反映する。
# 集計方法は画面で指定しない。役割とデータ型から自動で決める。

design:
  font: "Meiryo UI"
  main_color: "#2f3b52"
  sub_color_1: "#4a7dff"
  sub_color_2: "#c0c0c0"
  sub_color_3: "#8c9bb5"
  text_color_1: "#333333"
  text_color_2: "#555555"
  background_color: "#f5f5f5"  # 台紙（グラフの後ろの地）の色
  border_color: "#334455"  # 空なら枠線なし（キーごと出さない）
  filter_apply_button: false
  spacing: "narrow"        # wide（広い）/ narrow（狭い）。画面・受け手とも既定は narrow

datasources:
  "データソース名":
    folders:
      "フォルダ名":
        "元カラム": "表示名"
    renames:              # フォルダ未指定（フォルダへ入れず改名だけ）
      "元カラム2": "表示名2"
    hierarchies:            # 階層（ドリルダウン）。並びがドリルの順
      "商品階層":
        folder: "商品"      # 省略可。省略するとフォルダに入れない
        fields:
          - "カテゴリ"
          - "サブカテゴリ"
    calculations:
      - name: "利益率"
        formula: "SUM([利益]) / SUM([売上])"
        datatype: "real"
        role: "measure"
        folder: "指標"

dashboard:
  name: "ダッシュボード"
  width: "1600"
  height: "900"
  header:
    title: "ダッシュボード"
    height: "43"
    background_color: "@main_color"       # デザインルール参照。色コードも書ける
    font_color: "@background_color"
  rows:
    - name: "1段目"
      height: "300"
      distribute_evenly: false  # true なら幅を均等割り（width は書かない）
      areas:
        - kind: "worksheet"
          datasource: "データソース名"
          width: "600"
          sheet: "売上推移"
          chart: "draw_bar"
          params:
            item: "カテゴリ"
            metric: "売上"
            main_color: "@main_color"
          action:
            type: "filter"
            target: "明細"
            field: "カテゴリ"

kpi_tree:
  name: "KPI ツリー"
  datasource: "データソース名"
  align: "top"               # center / top。top ならエッジを描く
  root:
    sheet: "スコア|売上"
    params:
      main_metric: "売上"
      main_color: "@main_color"
      value_color: "@text_color_1"          # メイン指標の数値は文字色①
      title_background_color: "@main_color" # タイトル背景は主な色を複製
    children:
      - sheet: "スコア|利益"
        params:
          main_metric: "利益"
```

**最上位が `design` / `datasources` / `dashboard` / `kpi_tree` のセクションになっている。**
現行の `apply_field_config()` は最上位がデータソース名なので、この YAML はそのまま渡せない。

出力前に、そのファイルに出すタブの内容を検証し、エラーがあればダウンロードを止めて内容を出す。
データソースの検証はどのタブのダウンロードでも行う。

## 画面の出力と受け手の対応

**画面が出す値がすべて受け手の引数に届くかを確認した（2026-09-07）。**

| 画面 | 受け手 |
|---|---|
| `dashboard.name` / `width` / `height` | `create_dashboard()` |
| `dashboard.header.title` | `build_report(header_title=)` |
| `header.height` / `background_color` / `font_color` | `build_report(header_*=)` |
| `rows[].name` | `struct` のキー |
| `rows[].height` | `struct` の `height` |
| `areas[].kind` | 項目の `kind`。**同じ言葉を使う**（`worksheet` / `filter`） |
| `areas[].width` | 項目の `sheets` + `fixed_size`（1 枚の列にする） |
| `areas[].sheet` / `chart` / `params` | `draw_*()` の `name` と引数 |
| `areas[].field`（フィルター） | 項目の `field` |
| `areas[].action` | `dashboard.create_action()` |
| `design.font` | `set_default_font()`（`apply_config()` から適用済み） |
| `design` の色 | `draw_*()` の色引数。`@main_color` を実際の色コードへ解決して渡す |
| `design.spacing` | `build_report(content_style=, spacing_scale=)`。台紙は `wide` が `margin 8 / padding 16`、`narrow` が `margin 4 / padding 8`。`wide` のときはグラフごとのゾーンの余白も 1.5 倍（`spacing_scale=1.5`。0 は 0 のまま）。**`spacing` が無いときの受け手の既定も `narrow`**（2026-09-21 に画面と揃えた） |
| `design.filter_apply_button` | `build_report(filter_apply_button=)` |
| `kpi_tree.name` / `align` | `build_kpi_tree(dashboard_name=, align=, edges=align == "top")`。.hyper は同梱のものを `save()` が .twb の隣へ置く |
| `kpi_tree.datasource` + ノードの `sheet` / `params` | ノードごとに `draw_card()`（エリアと同じ `_draw_area()` を通す） |
| `kpi_tree.root` / `children` | `KpiNode` の親子 |
| `design.spacing`（KPI ツリー） | `build_kpi_tree(content_style=)`。ダッシュボードタブと同じ値 |

**1 段にグラフとフィルターを混ぜられる点が受け手に無かったため、`build_report()` の
区分値を項目ごとへ移した（2026-09-07）。** それ以外の食い違いは、ヘッダー文言の引数追加と
用語の統一で解消した。

## 実装済みと未実装の境界

受け手は `TwbWorkbook.apply_config()`。**画面が出す節はすべて届く（2026-09-07）。**

| 出力 | 受け手 |
|---|---|
| `datasources.*.folders` | `apply_field_config()` へ渡す |
| `datasources.*.renames` | フィールドを解決して `field.update(name=)`。フォルダへは入れない |
| `datasources.*.hierarchies` | `create_drill_path()`。**`folders` / `renames` / `calculations` の後**に作るので、改名後の名前や作ったばかりの計算フィールドを指せる。同じ名前の階層があれば作り直す（2 回当てても増えない、2026-09-21） |
| `datasources.*.calculations` | `create_calculated_field()`、同名があれば `update()` で上書き。**式が参照する計算フィールドから先に作る**ので、表の並び順は問わない（参照が循環していれば何も作らずに例外、2026-09-14） |
| `design.font` | `set_default_font()` |
| `design` の色・余白・適用ボタン | **`dashboard` / `kpi_tree` を組むときに使う。** 単独では届かないので、どちらも無い設定では名前をログに出して読み飛ばす |
| `dashboard` | `draw_*()` でシートを作り、`build_report()` で並べ、`create_action()` を張る |
| `kpi_tree` | ノードごとに `draw_card()` でカードを作り、`build_kpi_tree()` で並べる |

受け手が無い節はエラーにせず、名前を警告ログへ出して読み飛ばす。

### ダッシュボードの組み立ては 2 段

画面の 1 エリア = 1 シートで、`build_report()` は**既にあるシートを並べるだけ**。

```
1 段目  areas[].chart と params から draw_*() でシートを作る
        フィルターのエリアは set_filter() で登録する（全シートを作ってから）
2 段目  rows から struct を組み立てて build_report() へ渡す
3 段目  areas[].action から create_action() を張る
```

段の名前が空、または重複しているときは `段1` / `段2` を割り当てる。`struct` のキーは
一意でなければならないため。

### 2 周方式で同じ YAML を 2 度通すとき

`calculations` は同名があれば式・データ型・役割・フォルダを上書きする。2 度目に
「既に存在する」で止まると往復が回らないため。

`folders` / `renames` は「元カラム名 → 表示名」だが、元カラム名は表示名が変わった後も
フィールドの ID から引けるので、**適用済みの `.twb` へ同じものをもう一度渡しても止まらない**
（2026-09-14 実測。以前ここに書いていた「`NotFoundError` になる」は今の実装と合わない）。
画面を出し直すと、既にある計算フィールドとリネームは表に並び、毎回 YAML に出るが、上書きになるだけで増えない。

**`dashboard` / `kpi_tree` の節は上書きしない。** 同じ YAML をもう一度適用すると、最初のシートで
`worksheet already exists` になって止まる（止まる前に新しく作られるものは無い）。

**`folders` / `renames` の元カラム名がまだ無ければ、その項目だけ読み飛ばす**
（2026-09-23、ユーザーの指摘で変更。以前は `NotFoundError`）。`datasources:` は
`dashboard:` より先に適用されるが（`apply_workbook_config()`）、`build_waterfall`
の連番のように `dashboard:` 側が動的にフィールドを作る場合、画面が前回開いた
別の `.twb`（既にそのフィールドがある状態）から書き出した `folders` / `renames` を、
まだそのフィールドが無い `.twb` へ適用すると、`dashboard:` が実行される前に必ず
止まっていた。あれば名前を変える／フォルダへ入れる、なければ黙って無視する
（`_LOGGER.warning` には出す）。

**`calculations` の式が参照するフィールドがまだ無ければ、その計算フィールドごと
読み飛ばす**（2026-09-23、同じ理由）。`create_calculated_field()` / `field.update()` は
式中の `[名前]` 参照を `strict=True` で解決するため、`folders` / `renames` と同じ状況で
`NotFoundError: formula reference not found` になっていた。読み飛ばした計算フィールドを
別の式が参照していれば、それも連鎖して読み飛ばす。

### 役割から決まるもの

`role: dimension` は不連続（`discrete=True`）、`role: measure` は連続として作る。
画面では指定しない。
